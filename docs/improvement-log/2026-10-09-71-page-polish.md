# 2026-10-09 — [#71](https://github.com/kastoestoramadus/hocon-fmt/pull/71) — Playground polish: synced panes, taller default, TL;DR, build stamp

**Change:** The playground's two text panes share one height now: a `ResizeObserver` per pane feeds
a single Laminar `Var` that writes both panes' inline height, so dragging either resize grip
lengthens both, on the two-column desktop layout and the stacked phone one. Each pane's height is
read once at mount, so the observer's first report is not mistaken for a drag and the stylesheet's
default rules until one; the observer acts only on a height that differs from the shared one, and
the write waits one animation frame so a browser finishes delivering its resize observations — the
equality, not a guard flag, is what stops the feedback. The default height went from `14rem` to
`min(70vh, 32rem)`: 10.3 lines to 24.9 measured in headless Chromium at 1280x900, the phone's
`10rem` unchanged. The page opens with a 49-word TL;DR — one sentence, three bullets whose last
links the playground — and a copyable CLI quick start; the playground heading was already "Try it".
The four refusal explanations #67's review left behind (`LostInclude`, `MovedInclude`,
`ReservedName`, `NotUtf8`) are capitalised sentences that no longer repeat the status line's "no
file is written", and `ComponentSpec` reads its example counts from `ExampleData.more` instead of a
hand-kept list. The header carries a build stamp, "deployed <UTC date-time> · <short sha>" with the
sha linked to its commit: pages.yml passes `github.sha` and a `date -u` stamp into `sbt site/build`
as `HOCON_FMT_DEPLOY_*`, build.sbt bakes them into `BuildInfo`, and a build told nothing says
"local build". The stamp sits in the header's top-right on a desktop and in the flow under the
title at 390px.

**Look at again before a release:** The sync writes inline pixel heights once a drag has happened,
so a reader who then rotates a phone or resizes the window keeps the dragged height; if that ever
matters, the shared height could be dropped when the layout breakpoint changes. The quick-start
snippet is the CLI line docs/usage.md documents for the first release; check it when publishing
lands, as #69's entry says. The corner names whatever `github.sha` the deploy ran from — truthful
even on a `workflow_dispatch` re-deploy of an older commit, but it can look stale; the Pages
workflow's `changes` job is where to look if it ever confuses.
