# 2026-10-09 — [#86](https://github.com/kastoestoramadus/hocon-fmt/pull/86) — Republish at a release version into the local repositories

**Change:** `republishLocally` in `build.sbt` sets `publishM2Configuration` and `publishLocalConfiguration` to `withOverwrite(true)` for every project that publishes. Since the version became 0.1.0 rather than `-SNAPSHOT`, `sbt coreJVM/publishM2 javaApi/publishM2` failed against a `~/.m2` that `actions/setup-java`'s Maven cache had restored holding 0.1.0 ("the destination file exists and overwriting is disabled"), and a repeated `publishLocal` warned "You need to remove it from the cache manually" and left the old jar in place while reporting success. The release is untouched: `publish` and the `publishRelease` alias upload to the Central staging repository, which keeps refusing to overwrite, and the Gradle, Maven and Mill builds read these repositories instead of writing them.

**Look at again before a release:** Remove the overwrite for the local repositories? It is needed only for CI caches; the release itself uploads once. The setting is scoped to `guardPublish`, so deleting `republishLocally` restores the refusal in one place.
