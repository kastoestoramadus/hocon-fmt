# 2026-10-09 — PR #70 — Unreadable files fail the run; directories are walked

**Change:** `hocon-fmt --check missing.conf` used to report the file as refused and exit 0; a missing or unreadable path is not a refusal of any content, so it now reports `cannot read <path>: <reason>` on stderr and exits 2, as a usage error does, leaving 1 to mean unformatted — a typo in a CI script's path cannot pass silently any more. `ReadFailure` turns the JVM's typed exceptions and Node's errno strings into the words (`no such file`, `access denied`, `is a directory`). A directory argument is walked for `*.conf` and `*.hocon`, as prettier and ruff walk: hidden entries and what `.gitignore` excludes are skipped, a nested `.gitignore` can re-include, a symlinked directory is not followed, and a file named on the command line is examined even when ignored. The ignores are the `.gitignore` files from the checkout root (the directory holding `.git`, where the walk up stops, as the style lookup does) down to the argument and below; a deeper file's match beats a shallower one's. Tests first on JVM, Node and Native (`CmdApiSpec`, `GitIgnoreSpec`, `CliAcceptanceSuite`), red then green; `sbt -batch -J-Xmx5g test scalafmtCheckAll scalafmtSbtCheck` and `scripts/pre-commit-e2e.sh` green.

**Look at again before a release:** the walk reads `.gitignore` files only — `core.excludesFile`, `.git/info/exclude` and global ignores are out of scope, as they are for prettier and ruff; revisit if a repository relies on them. A directory excluded by a pattern cannot be re-included below it (`gen/` then `!gen/keep.conf`), which is git's own rule, and an unreadable `.gitignore` is skipped rather than failing the run. The unreadable exit code 2 is the one usage errors already use; check the docs and the pre-commit hooks still read as intended.
