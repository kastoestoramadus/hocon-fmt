# 2026-10-15 — [#147](https://github.com/kastoestoramadus/hocon-fmt/pull/147) — Include checks share path and scope indexes

**Change:** Moved-include checks use exact canonical sets of preceding paths; shadowed-include checks index each object/array scope once and search eligible include positions. Frozen test-only implementations preserve complete results and refusal priority on adversarial/generated inputs, repository fixtures and an optional external corpus. For 2,000 include/field pairs, local JVM moved/shadowed times fall from 2,916/4,932 ms to 60/40 ms; fitted exponents over 100–2,000 includes fall from 1.98/2.06 to 1.34/1.24. Full JVM formatting falls from 6.43 s to 261 ms and Native CLI time, including startup, from 17.02 s to 1.16 s under an 8 GiB/no-swap scope. These are shared-machine medians, not latency guarantees.

**Look at again before a release:** Rerun the scaling guards and frozen differential oracle when changing include masking, origin ordering or sconfig. Repeat the optional external corpus with `HOCON_INCLUDE_CORPUS`; the oracle deliberately shares the unchanged parser and masking, so it establishes equivalence of these checks rather than independently validating those components.
