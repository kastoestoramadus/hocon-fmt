# Data and markup formatters: history, tests and API (pass B)

What this is: for one family of formatters — prettier (JSON/YAML/Markdown), Biome, dprint (core and its JSON/JSONC and Markdown plugins), yamlfmt, `buf format`, sqlfluff's layout rules, and xmllint-style XML formatters — the fix history since 2022, how each tests, candidate test cases rendered in HOCON, and the API/integration surface, compared to hocon-fmt.

Method: each repository was shallow-cloned (`--filter=blob:none --shallow-since=2022-01-01`) into the task directory; history is from `git log`/`git show` in those clones, issues and PRs from `gh api` (and the GNOME GitLab REST API for libxml2) in this session; every URL cited was fetched here. Dates are commit/merge dates. HOCON renderings are ours, written for this document, not copied from the tools' test text; each tool's license (prettier MIT, Biome MIT/Apache-2.0 dual, dprint and its plugins MIT, yamlfmt Apache-2.0, buf Apache-2.0, sqlfluff MIT, libxml2 MIT, xml-formatter MIT, yq MIT) covers its inputs. "Unverified" marks a claim we could not settle by running or opening something.

## prettier — JSON, YAML, Markdown
prettier/prettier, MIT, 52.4k★, repo created 2016-11-29; HEAD `c3d3652`, 2026-10-09. Stance: opinionated and hardly configurable; every option is a philosophical defeat. The data/markup languages share the whole comment-attachment and printing engine.
### History: ten instructive fixes
| what broke (minimal trigger) | root cause | lesson for hocon-fmt |
|---|---|---|
| A **comment-only JSONC file is refused**: `// Comment` → `SyntaxError: Unexpected token (1:11)` ([#17269](https://github.com/prettier/prettier/pull/17269), 2025-03-20) | the parser treated trivia-only input as an empty program and errored | hocon-fmt refuses every comments-only file (`LostComment`). Prettier decided such a document must format. Worth a decision with a corpus count, not a workaround. |
| **Block-scalar trailing whitespace removed**: `foo: \|-\n  value  \n` loses the two trailing spaces ([#19764](https://github.com/prettier/prettier/pull/19764), 2026-08-24) | the AST massage trimmed line ends; inside `\|`/`>` whitespace is content | whitespace inside a content-bearing string is meaning. HOCON's triple-quoted strings are the analogue; hocon-fmt normalises them to an escaped single line — the same class, property-test it. |
| Markdown link corrupted: `[link](<\<(\\>)` is rewritten, `\` and `<` dropped ([#19150](https://github.com/prettier/prettier/pull/19150), 2026-06-02), **reverted** ([#19470](https://github.com/prettier/prettier/pull/19470), 2026-06-26: "too many unnecessary changes on MDN … breaks editability"), re-landed ([#19482](https://github.com/prettier/prettier/pull/19482), 2026-08-15) | URL escaping lost characters; the fix annoyed more users than the corruption | a clever rewrite can be worse than the bug. Preserve the author's spelling or refuse; never invent an equivalent spelling. |
| Link escape **not idempotent**: `[test](/hello?foo&quot\;bar)` changes again on the second format ([#19849](https://github.com/prettier/prettier/pull/19849), 2026-08-18) | pass 1 printed an escaped entity, pass 2 dropped it (the changelog prints both passes) | the second-pass check must run on the printed text; this is exactly `Refusal.UnstableOutput`. |
| Comment between a flow-mapping key and its `:` **moved after the value**: `{ "foo" # comment` / `:bar }` → `{ "foo": bar } # comment` ([#18324](https://github.com/prettier/prettier/pull/18324), 2025-11-27; found by the shared yaml-test-suite corpus) | no printer form kept an explicit key with a comment between key and `:` | a comment at a structural boundary forces a form that keeps attachment. HOCON's analogue — a comment between key and separator — has no attachment in sconfig's tree: pin the verdict. |
| Blank lines between list items and nested sub-lists **removed**, turning loose lists into tight ones ([#17857](https://github.com/prettier/prettier/pull/17857), 2026-06-04) | blank-line handling in `print/children.js` | a blank line can be semantics. HOCON has no loose/tight rule, but this is why dropping blank lines is documented rather than assumed harmless. |
| Empty line before a trailing comment **dropped** (`only: issues` / blank / `# Comment` → comment pulled up) ([#17843](https://github.com/prettier/prettier/pull/17843), 2025-09-19; again after block scalars [#19205](https://github.com/prettier/prettier/pull/19205), 2026-06-03; again at HEAD [#20243](https://github.com/prettier/prettier/pull/20243), 2026-10-09) | the comment printer normalised the preceding empty line away | blank-line-above-comment is a comment-attachment signal — the very one sconfig uses to drop the comment, hocon-fmt's commonest refusal. Prettier needed four fixes for this one shape. |
| Anchor/tag order **swapped**: `&anchor1 !!str Value1` → `!!str &anchor1 Value1` ([#19599](https://github.com/prettier/prettier/pull/19599), 2026-07-19) | the printer emitted properties in a fixed order | do not reorder syntactic forms the author chose. hocon-fmt changes `:`→`=`, `//`→`#` by decision; everything else stays, because "meaning preserved" is not "spelling preserved". |
| Duplicate YAML keys became **allowed** instead of an error ([#18417](https://github.com/prettier/prettier/pull/18417), 2025-12-03) | a strict spec reading refused common input | duplicate keys are common; refusing them makes the tool unusable. hocon-fmt formats them and reports them separately — the same split, with `--fail-on-duplicates` as the opt-in. |
| Unstable comment printing: a fix, its **revert**, a later fix ([#18395](https://github.com/prettier/prettier/pull/18395), 2025-12-02; [#19273](https://github.com/prettier/prettier/pull/19273) reverted by [#19274](https://github.com/prettier/prettier/pull/19274), 2026-06-03) | comment attachment/print order is where fixed points break; the revert also edited the known-unstable allowlist | comment handling is the least stable part of every formatter here; an idempotence property over comment-heavy documents beats examples. |
Recurrence: ~668 fix-subject commits since 2022 and 36 reverts, but the blank-line/comment shape alone re-appears in 2024, 2025 (twice) and 2026 (three times); Markdown list-indentation drift was fixed three times in September 2026 (#19647, #19990, #19987) and once more at HEAD (#20243); 60 open issues carry `area:idempotency`. For this family: 11 commits mention "comment", 5 "blank line", 4 "newline".
### How it tests
- `tests/format/{json,yaml,markdown}/<case-dir>/format.test.js` calls the global `runFormatTest`; a case set is every file in the dir (plus inline `snippets`); snapshots are Jest files under `__snapshots__/`, `_errors_/` dirs snapshot the thrown message. Counts here: json 43 fixtures, yaml 361, markdown 282.
- `tests/config/format-test/run-test.js` composes five checks: `test-format` (snapshot), `test-second-format` (format the output again → identical), `test-ast-compare` (re-parse and compare), `test-bom` (BOM prefix changes nothing else), `test-end-of-line` (`\r\n`/`\r`). **The four extra checks run only under `FULL_TEST`** (CI: ubuntu + Node 26); known-bad cases are allow-listed in `failed-format-tests.js`, and the CLI's `--debug-check` is the same check on demand.
- Corpora: `json-test-suite`, `yaml-test-suite` (whole shared suite, 3 cases allow-listed with bug links), `commonmark-test-suite`, `gfm-test-suite`. **No fuzzing in-repo**; regression testing lives in the separate `prettier/prettier-regression-testing` repository. Snapshot update: `jest -u`. CI: `dev-test.yml`/`prod-test.yml`, 15-minute timeout, ubuntu/macos/windows.

### API and integrations
- CLI: `--check/-c`, `--write/-w`, `--list-different/-l`, `--stdin-filepath`, `--range-start/--range-end`, `--debug-check` (format twice + AST compare), `--ignore-unknown`, `--ignore-path` (`.prettierignore` and `.gitignore` by default), `--config`, `--insert-pragma`, `--require-pragma`, `--cache`. Exit codes: **0** clean; **1** unformatted under `--check`/`--list-different`, or an invalid option/config; **2** parse error, unmatched pattern, read/write failure.
- Config resolved upward per file: `.prettierrc` (JSON/YAML/TOML/JS), `prettier.config.js`, `package.json#prettier`, `overrides` per glob; no global config. Ignore pragma per language: Markdown `<!-- prettier-ignore -->` and `-start/-end`, YAML `# prettier-ignore`, **JSON none** (`hasIgnorePragma: () => false`), so `requirePragma` cannot exempt JSON.
- Programmatic: `format`, `check`, `formatWithCursor`, `resolveConfig`, `getFileInfo`, `getSupportInfo`. Integrations: pre-commit via lint-staged/pretty-quick/Lefthook (documented, not shipped as hooks), CI via autofix.ci and reviewdog, editors via the official VS Code extension and many others; **no official LSP**. Pins: yarn 4, committed lockfile, Renovate with `:pinDependencies`.
- Most wanted (by reactions, fetched 2026-10-09; prettier has no `type:enhancement` label): #7475 "Change `useTabs` to `true` by default" (870), #5246 void-tag option (448), #5287 "Support prettier-ignore-start/end for other languages (not only Markdown)" (442), #265 "Wrap comments" (357). Family-specific: `lang:yaml` #9853 (47), #16126 open "yaml with folded multiline string and `--prose-wrap always` improperly wraps (and is not idempotent)" (3); `lang:markdown` #15479 (53), #8480 (40). Range formatting and comment wrapping are the long asks. Ideas: per-fixture second-format + AST + BOM + CRLF variants (S); `--debug-check` as a CLI flag (S); a `failed-format-tests.js`-style allowlist register (S).

## Biome — JSON, Markdown, YAML
biomejs/biome, MIT/Apache-2.0 dual, 25.9k★, repo created 2023-07-27 (successor of Rome). Stance: "prettier-compatible" opinionated formatter plus linter; YAML and Markdown formatting arrived in 2026.
### History: eight instructive fixes
| what broke | root cause | lesson for hocon-fmt |
|---|---|---|
| Markdown blockquote fenced code **not idempotent**: each pass indented the fence deeper (`> code` → `  > code` → …) ([#11493](https://github.com/biomejs/biome/pull/11493), 2026-08-25) | fences were formatted under the blockquote's indent; the fix resets to root indent | indentation drift under nesting is the classic fixed-point bug; test `format(format(x))` on nesting-heavy inputs. |
| Trivia after a **suppressed** node thrown away (a `biome-ignore`'d node lost its trailing comment) ([#9790](https://github.com/biomejs/biome/pull/9790), 2026-04-03) | suppression skipped the node and its trailing trivia | an ignore/suppression path must suppress *edits*, never *text*; if hocon-fmt gets a pragma, this is its failure mode. |
| Idempotence formatting embedded snippets ([#9532](https://github.com/biomejs/biome/pull/9532), 2026-03-17; [#9902](https://github.com/biomejs/biome/pull/9902), 2026-04-10) | fixes into embedded snippets lost the indentation to re-apply; the fix threads the required indent through `fix_all` | embedded/indented content needs the indent passed in; "format the fragment, paste it back" breaks the fixed point. |
| The last comment of a document **printed twice** ([#11188](https://github.com/biomejs/biome/pull/11188), 2026-08-03); duplicate comments after Svelte blocks ([#11930](https://github.com/biomejs/biome/pull/11930), 2026-09-24); dropped initializer comments ([#3397](https://github.com/biomejs/biome/pull/3397), 2022-10-11) | comment ownership at end-of-document/block boundaries is ambiguous | count comments in and out; duplication is as bad as loss, and a loss-only check (hocon-fmt's `LostComment`) does not see it. A multiset comparison is the invariant. |
| The Markdown parser **synthesised an inline node** out of an HTML comment ([#11337](https://github.com/biomejs/biome/pull/11337), 2026-08-14) | the parser invented a node and the comment's text leaked into output | parser bugs surface as formatter corruption; validate the output by re-parsing. |
| A YAML flow scalar overflowing the width was **moved below its key** ([#11140](https://github.com/biomejs/biome/pull/11140), 2026-08-31) | a line-width decision restructured the document | layout must never restructure; wrap/overflow or refuse, never relocate (HOCON: never split a field at a width boundary). |
| **Stack overflow** cleaning up a deeply nested tree ([#11368](https://github.com/biomejs/biome/pull/11368), 2026-09-01) | recursive `Drop` over a rowan tree; the same behaviour went back years | depth is untrusted input; iterative cleanup and a deep-nesting test (hocon-fmt's Scala.js ≥32 refusal shows the platform difference). |
| YAML formatting shipped in 2026 with comment features designed in from the start: middle comments (#11063), block-scalar trailing comments ([#11058](https://github.com/biomejs/biome/pull/11058), 2026-07-29), suppression comments ([#11842](https://github.com/biomejs/biome/pull/11842), 2026-09-21) | the YAML printer was new, so comment handling was built with the tree | comment handling designed with the tree beats comment handling retrofitted; it is the same lesson as the CST idea in docs/ideas.md. |
Recurrence: 3424 fix-subject commits, 86 reverts, and idempotence was fixed at least three times in 2026 (#11493, #9532, #9902); the comment-at-a-boundary class spans 2022-10 → 2026-09. The JSON side has its own repeats: comments in empty arrays/objects dropped ([#1323](https://github.com/biomejs/biome/pull/1323), 2023-12-23), a trailing-comma decision made in [#4803](https://github.com/biomejs/biome/pull/4803) and **reversed** in [#6683](https://github.com/biomejs/biome/pull/6683) (2025-07-03), and parser panics on unterminated strings (#2357) and triple quotes (#2606) in 2024 — one more reason to pin each rule with a test.
### How it tests
- Spec tests per formatter crate: `crates/biome_json_formatter/tests/specs/json/**/*.{json,jsonc}` (31 inputs + 31 `.snap` at HEAD; the `prettier/` tree 38 + 38 `.prettier-snap`), driven by `spec_tests.rs` through `biome_formatter_test`; an optional `<case>.options.json` pins formatter options, and `prettier_tests.rs` compares against prettier's snapshots.
- The shared harness checks **idempotence explicitly**: `spec.rs` formats a second time and fails with "Formatter is not idempotent: re-formatting produced different output" (`check_reformat.rs` prints the diff); ranges and files with errors skip the check.
- Fuzzing exists for JSON: `fuzz/fuzz_targets/rome_format_json.rs` asserts the output re-parses without errors **and** that a second format is identical; it is not run by the CI workflows (they trigger on `fuzz/**` changes only), so it is a tool rather than a gate. Other levers: `e2e-tests/` (CLI) and cargo tests on GitHub Actions.

### API and integrations
- CLI: `biome format` **checks by default** — it prints a diff and exits failure — and `--write` (or `--fix`) is what writes; there is no `--check` flag (`biome check` is a different command: format + lint + assist). Exit codes: `ExitCode::SUCCESS`, `FAILURE` when any diagnostic is error-level (`biome_cli/src/diagnostics.rs`); on stdin an ignored path echoes the content with a warning, an unsupported formatter echoes it and errors.

Programmatic: the Rust crates (`biome_formatter`, per-language crates) and a WASM build. Integrations: VS Code and IntelliJ extensions, pre-commit repo, `setup-biome` action, LSP server in the binary (`crates/biome_lsp`), plugins via GritQL. Pins: `biome.json` `$schema` plus the CLI version.

## dprint — core, dprint-plugin-json, dprint-plugin-markdown
dprint/dprint, MIT, 4.1k★ (repo created 2019-06-16); plugins are separate MIT repos, shipped as WASM. Stance: a fast, configurable formatter host; the plugins own formatting, the core owns files, config and the LSP.
### History: ten instructive fixes
| what broke | root cause | lesson for hocon-fmt |
|---|---|---|
| Link reference definitions **silently deleted** — definitions before the first parse event (a common layout, at the top of a file) were dropped, turning working links into dangling ones ([#205](https://github.com/dprint/dprint-plugin-markdown/pull/205), 2026-08-22) | the definition scan started from the previous event's end, `None` on the first iteration, so the region before the first event was never scanned | silent deletion is the worst failure class; the right test is "every construct in the corpus is present in the output", not only "the output parses". |
| Blank line before a trailing comment at the end of an object/array **dropped** while the same shape elsewhere was preserved ([#52](https://github.com/dprint/dprint-plugin-json/pull/52), 2026-06-17) | the end-of-container path had its own blank-line rule | special-casing container ends loses the comment's separation — prettier's #17843 in another codebase. |
| Comments between a JSONC name/colon and value/comma **dropped** ([#51](https://github.com/dprint/dprint-plugin-json/pull/51), 2026-06-17; issue [#24](https://github.com/dprint/dprint-plugin-json/issues/24): "Formatting JSONC can lose comments yet still indicate success") | trivia not carried across the value boundary | comments between key and value, or value and comma, are attachment gaps in every parser; HOCON's "comment between key and `=`" is a refusal case to pin. |
| An **ignore comment did not stop trailing-comma edits**: a `// dprint-ignore`'d element still had its comma added/removed ([#69](https://github.com/dprint/dprint-plugin-json/pull/69), 2026-09-15; issue #9) | comma logic ran in a pass outside the ignored span | an ignore pragma must cover all edits to its span, including the separator after it. |
| `//` **comment keys** in package.json sorted away from the field they describe ([#73](https://github.com/dprint/dprint-plugin-json/pull/73), [#74](https://github.com/dprint/dprint-plugin-json/pull/74), 2026-10-01; issue [#72](https://github.com/dprint/dprint-plugin-json/issues/72)) | sorting treated a comment key as an unknown field; the fix makes it travel with the field below | ordering algorithms need comment awareness; a key that is a comment must move with its field. (hocon-fmt never sorts; `IncludeOrder` refuses movement of includes for the same reason.) |
| Blockquote marker lost when it does not start a line, and for empty block quotes ([#188](https://github.com/dprint/dprint-plugin-markdown/pull/188), 2026-08-22; regression test [#208](https://github.com/dprint/dprint-plugin-markdown/pull/208)) | the printer assumed the marker starts the line | an empty construct still needs its delimiters (empty HOCON object, empty array, `""`). |
| Emphasis lost after delimiter-list bookkeeping: `*a_)b*_c_` ([#274](https://github.com/dprint/dprint-plugin-markdown/pull/274), 2026-09-03) and an HTML block opened by `<script>` swallowing the document because its end tag was matched literally ([#275](https://github.com/dprint/dprint-plugin-markdown/pull/275)) | an index into a list mutated by wrapping; a lexer spec detail | **both found by comparing the parser with commonmark.js on random documents** ([#271](https://github.com/dprint/dprint-plugin-markdown/issues/271)) — differential testing finds what examples never will; HOCON's reference is sconfig. |
| The JSON plugin wrote the **BOM back into the output** ([#37](https://github.com/dprint/dprint-plugin-json/pull/37), 2024-05-26), while the CLI *re-added* a BOM after formatting and had its BOM handling deleted to become byte-exact ([#844](https://github.com/dprint/dprint/pull/844), 2024-05-05) | two layers both claimed the bytes before the text | a BOM is a byte-level contract owned by one layer; hocon-fmt decodes strictly and drops the BOM in one place, and a plugin/adapter must not re-add it. |
| A parse **panic on multiple top-level values** ([#20](https://github.com/dprint/dprint-plugin-json/pull/20), 2023-06-09) and **raw control characters written through** unescaped ([#67](https://github.com/dprint/dprint-plugin-json/pull/67), 2026-09-13) | a parser assumption; an escape check that did not cover C0 bytes | malformed and adversarial input must be refused or escaped, never passed through or crashed on. |
| Non-breaking spaces crashed debug builds ([#157](https://github.com/dprint/dprint-plugin-markdown/pull/157), 2026-01-29) | a debug assertion on the character class | unicode input is data, not an assertion; keep a unicode case in the property suite. |
Recurrence: the Markdown plugin has 87 fix-subject commits and was still fixing non-idempotence in 2026-08 (#221 setext heading with a comment, #222 code span in a list); the JSON plugin's five comment fixes all land in 2026-06 → 2026-10, i.e. the comment surface was patched repeatedly in one season.
### How it tests
- Spec files are `.txt` documents: `-- /file.jsonc --`, optional config, input, `[expect]`, and the runner (`dprint-plugin-json/tests/test.rs`) passes `format_twice: true` — **every spec asserts idempotence**. Layouts: `tests/specs/{comments,object,array,strings,numbers,json5,package_json,range,general}`.
- The Markdown plugin adds: `parser_specs/`, `commonmark_spec_check.rs` (conformance against the CommonMark spec text), `html_parser_spec_test.rs`, `newline_test.rs`, `nesting_test.rs` (documents nested 63 deep — one below the parser limit — must not overflow the stack), and `corpus_check.rs`, which formats **every `.md` of a corpus twice** and reports `PANIC`, `ERROR`, `NOTIDEMPOTENT`, `ERROR2`, `PANIC2`, and `LOSTTEXT` when the letters that went in do not all come back out (`CORPUS=<dir>` selects the tree).
- The core's own specs live under `crates/dprint/tests/specs/` (in-source `#[test]`s with a `TestEnvironmentBuilder`; `88e2baf` made them idempotent in 2022).
- The core also guarantees the fixed point as a **product behaviour**: `crates/dprint/src/format.rs` `EnsureStableFormat` loops formatting until the text stops changing and bails after 5 tries ("Formatting not stable. Bailed after 5 tries."); `--skip-stable-format` opts out (and forces incremental off). That is hocon-fmt's `UnstableOutput` refusal, reached from the other side — the difference is dprint writes nothing and reports, where hocon-fmt refuses the file.

### How they test
- libxml2: 51 `test/*.xml` inputs paired with 683 `result/*` goldens, driven by `runtest.c`; a case is parse → `xmlSaveFile` → compare, then **re-parse the output and compare again** (round trip, not idempotence, and not `--format`). CI is GitLab-only (~30 jobs incl. sanitizers); no pre-commit hook.
- xml-formatter: 42 `*-input.xml`/`*-output.xml` pairs under `test/dataN`, and `test/index.ts` asserts formatting **twice** for every one (`assert.equal(formattedContents2, expectedContents, 'Idempotence test for …')`). Caveat worth copying: `test/data16/*` is referenced by the test file but the directory does not exist, so that context silently checks nothing — verify that declared fixture globs are non-empty.
- yq: `pkg/yqlib/xml_test.go`, 64 `formatScenario`s as inline input/expression/expected; round-trip tests exist, idempotence is not asserted.

### API and integrations
- xmllint: `--format`, `--pretty 0|1|2` (2 adds `XML_SAVE_WSNONSIG`), `--noblanks` (loses content), `--noent`, `--recover` (best effort — the opposite of a refusal), `--encode`, `--nocdata`, `--dropdtd`, `-` for stdin; well-formedness failure is exit **4**, other codes per subsystem. Library: `xmlSaveFormatFile`, `xmlDocDumpFormatMemory`, `xmlSaveToFd/Buffer` + `xmlSaveSetIndentString`. No pre-commit hook; treefmt-nix wires it up as a formatter, hence #1030.
- xml-formatter: **library only** (no `bin`); options `indentation` (default 4), `lineSeparator` (**default `\r\n`**), `collapseContent`, `ignoredPaths`, `filter` (a callback, used to drop comments), `whiteSpaceAtEndOfSelfclosingTag`, `throwOnFailure`, `strictMode`, `forceSelfClosingEmptyTag`, `attributeQuotes`; `formatXml.minify`; invalid XML either throws or returns the input unchanged.
- yq: `-p xml -o xml`, `-I/--indent`, `--xml-attribute-prefix`, `--xml-content-name`, `--xml-strict-mode`, `--xml-keep-namespace`, `--xml-raw-token`, `--xml-proc-inst-prefix`, `--xml-skip-proc-inst`, `--xml-skip-directives`; no formatting-check mode, so no exit-code contract for style. Most wanted: libxml2 #852 (formatting quality) and #1030 (write only if changed); #989 asks for configurable indentation; xml-formatter's top issue is memory use on large documents ([#71](https://github.com/chrisbottin/xml-formatter/issues/71), open). Ideas: a per-fixture idempotence assertion inside `GoldenFileSpec` (S); a "declared fixture exists and the glob is non-empty" check in the test runner (S — the `data16` dead context); a README statement of exactly what the formatter preserves and refuses (S).

## Comparison with hocon-fmt
| concern | hocon-fmt today | this family's contract |
|---|---|---|
| check mode / exit codes | `--check` exit 1 unformatted, 2 usage/unreadable | prettier 0/1/2; sqlfluff 0/1/2; buf `--exit-code`; Biome checks by default and fails on an error diagnostic; dprint 0/1, 10–14 for usage/config/plugin/no-files, 20 for `check` differences; yamlfmt `-lint` exit 1 |
| write only if changed | verdict; refusals write nothing | buf #3058 fixed it; xmllint #1030 still broken — the most-cited plugin complaint |
| refuse vs best effort | typed `Refusal`, never writes | sqlfluff discards fixes on non-convergence; buf disables format on files with errors; dprint loops to a stable text and, after 5 tries, bails and writes nothing; prettier and Biome always write something |
| idempotence checked in tests | `HoconFormatterInvariantsSpec` + 1000-document properties | prettier second-format + AST (only under `FULL_TEST`); Biome per-spec idempotence and a JSON fuzz target; dprint `format_twice` in every spec plus a product-level stable-format loop; xml-formatter twice per pair |
| comment preservation | `LostComment` (loss only) | nobody checks duplication; Biome needed three fixes for printed-twice comments |
| output validation | re-parse + stability + comment/include checks | sqlfluff reparse per segment + loops with a limit; prettier `--debug-check`; most others only snapshot |
| ignore pragma | none | prettier (per language), Biome `// biome-ignore`, dprint `// dprint-ignore`, sqlfluff `-- noqa`; yamlfmt none |
| range formatting | none | prettier has it (editor-driven); sqlfluff per-rule ranges |
| stdin | `--stdin` (+ Node/native) | prettier and buf `--stdin-filepath`; dprint `--stdin <ext>`; yamlfmt `-in` |
| config discovery | `.hocon-fmt.conf` upward, `.git` stops it | prettier upward per file; dprint upward with `--config`; sqlfluff `.sqlfluff`/pyproject; yamlfmt home config — hocon-fmt matches the strictest |
| LSP / editor | none (ideas) | dprint and Biome ship an LSP; buf bundles one; prettier uses editor extensions |
| pre-commit | both hook families, e2e-tested | dprint's top request is pre-commit integration; yamlfmt and sqlfluff ship hooks; hocon-fmt is ahead here |
| build tools | sbt, Gradle, Maven, Mill, Spotless snippet | buf explicitly supports Gradle Spotless via `--stdin-filepath` |
| style versioning | one version everywhere; `.hocon-fmt.conf` options | buf: no options; prettier: config + exact pin; dprint: plugin URL pinned; sqlfluff: config + rule selection |
