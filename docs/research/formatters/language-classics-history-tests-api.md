# Classic formatters: history, tests and API

Pass B for the classic-language formatter family — gofmt (`go/printer`, `go/format`, `cmd/gofmt`),
rustfmt, Black, `ruff format`, scalafmt, google-java-format, clang-format. A sibling pass (A)
profiles the same family's bug classes from the trackers; this file mines the repositories
themselves: the fixes since 2022, the test architecture, and the API and integration surface.
Every tool section ends with `### Ideas to migrate`; the cross-tool table and the ranked list are
at the end.

They are the family that imposed a style on a language, and all seven carry a long public history
of comment-placement and idempotence bugs — the two classes hocon-fmt's "refuse rather than
corrupt" promise exists to avoid. gofmt and google-java-format show that "no configuration" is a
viable product; Black, ruff and clang-format show the escape hatch users demand anyway
(`# fmt: off`, `// clang-format off`); scalafmt is the closest tool to us technically (Scala,
HOCON config, sbt and Mill plugins, a version pinned in the config), and rustfmt is the closest in
spirit (`LostComment`, "not formatted because a comment would be lost").

**Method.** Each repository was shallow-cloned (`--filter=blob:none --shallow-since=2022-01-01`)
into the task directory and mined with `git log --grep` and `git show` over the formatter's own
paths; the test trees were read from the same checkouts; API claims come from source files, CLI
parsers and the repos' own docs. Commit shas and file URLs are pinned to the clone HEAD below
(clones deleted after the task). Where an issue/PR number comes only from a squash-merge subject
or commit message, the section says so; PR links for ruff are `.../pull/<n>` for that number.
GitHub's API was rate-limited for most of this pass, so the clones are the primary evidence and
"unverified" marks what could not be confirmed live. Nothing was executed: these toolchains are
not installed here, so behaviour claims come from code and tests, not runs. **No test text was
copied**: every HOCON rendering in the tables is written for this file. hocon-fmt is GPL-3.0;
the licences of the mined test sources — gofmt BSD-3-Clause, rustfmt MIT OR Apache-2.0, Black
MIT, ruff MIT, scalafmt Apache-2.0, google-java-format Apache-2.0 (its `-diff.py` LLVM/UIUC),
clang-format Apache-2.0 WITH LLVM-exception — permit reading for ideas only.

## gofmt

**History: the ten fixes worth reading.** Each line: what broke — trigger; cause; sha (link, date); lesson.

- **A doc comment that reformats to nothing squashed the whitespace before it** — trigger `func _() {}` / blank / `//` / `func _() {}`; `formatDocComment` can return an empty list and the loop then wrote neither comment nor preceding whitespace, so the next declaration lost its separating blank line; `557244cef70e` ([go.dev/issue/53059](https://go.dev/issue/53059), 2022-05-24); lesson: "this comment has nothing to attach to" must become a visible refusal, never a silent empty render.
- **Doc-comment formatting was not idempotent, and its fix changed unrelated output** — trigger a comment block with a `//go:` directive in the middle; "is this a doc comment?" was decided from column and adjacency only, so pass 1 left the text alone and pass 2 reflowed it; `c3f16307b3ff` (2024-09-04) reverted by `ad6ee21bbf3e` (2024-09-10) ([go.dev/issue/69382](https://go.dev/issue/69382)); lesson: an idempotence bug lives in a heuristic and its fix is a new bug when it moves other output — the property must run on every fixture, not a curated list.
- **An indented comment inside a struct was mistaken for a doc comment** — trigger `type T struct { /* unindented */ X int }` under a doc comment; the doc test keyed off "unindented and abutting" without checking the next token's kind; `c1f0b9bdbac0` (authored 2024-04-20, merged 2026-05-18) ([go.dev/issue/52605](https://go.dev/issue/52605)); lesson: comment placement must key off syntax context — without a property test this stayed open two years.
- **Comment bytes were rewritten into smart quotes** — trigger a doc comment containing ` `` ` or `''`; the `go/doc/comment` parser turned them into “ ”; fenced-code case patched in `6c7b223c2bfa` (2022-06-03), the rewriting removed in `9f1012d9a1aa` (authored 2025-12-23, merged 2026-07-15) with "Characters important to programming languages should not be mangled" ([go.dev/issue/76975](https://go.dev/issue/76975)); lesson: never rewrite bytes inside a comment; render every comment verbatim, Markdown included.
- **Printed output reparsed as different code** — trigger an AST for `<-((<-chan int)(nil))` with no `ParenExpr`; `expr1` emitted `<-<-chan int`, a receive of a receive; `0c64ebce7e70` ([go.dev/issue/63362](https://go.dev/issue/63362), 2023-10-04); lesson: the output check must compare re-parsed meaning, which is what hocon-fmt's masked re-parse + `Refusal.BrokenOutput` does.
- **The printer emitted invalid syntax and panicked on trees it was handed** — `&ast.GenDecl{Tok: var}` printed as a bare `var`, and `type _[P ((*T)),]` panicked in `combinesWithName`; `ff7986d67` ([go.dev/issue/63566](https://go.dev/issue/63566), 2023-10-17), `700920bbb73b` ([go.dev/issue/69206](https://go.dev/issue/69206), 2024-09-02); lesson: "never write a broken file" needs totality — a refusal, never an almost-token or a crash, for any tree the pipeline can build.
- **A failed `-w` rewrite changed owner and permissions** — trigger `gofmt -w` on a file the process may not write; a failed rename-and-restore path changed ownership; now the original bytes are written back and the backup is only removed on success; `2693ade1fad8` ([go.dev/issue/60225](https://go.dev/issue/60225), 2023-05-16); lesson: the write path is part of the promise and gets its own test (mtime unchanged after a refused write).
- **Whole-file rewrites through a symlink truncated the target wrongly** — the truncate decision compared against the link's size; fix `5f711bfdb35c` (2026-05-29), reverted the same day (`eb343e2fa0e8`, "Doubts about correctness of fix"), fixed properly in `0af88e584cd6` (2026-07-08) by always truncating to what was written ([go.dev/issue/79735](https://go.dev/issue/79735)); lesson: a write-path heuristic that can be wrong is worse than none; a symlinked HOCON file must be a test.
- **The same input formatted differently on different CPUs** — a composite literal whose element sizes made `math.Exp(math.Log(95))` exactly 95.0 on arm64 but 94.999… on amd64, flipping alignment; replaced with `Frexp`/`Ldexp`, `a8f99ef1f6e5` ([go.dev/issue/77959](https://go.dev/issue/77959), 2026-03-09); lesson: one core shipped to JVM, JS and Native — any float, map iteration or locale in a layout decision breaks "same input, same output"; pin it with a cross-platform golden.
- **`-d` printed a diff yet exited 0** — `gofmt -d` in a check loop could never fail; the diff branch now returns `errFormattingDiffers` → exit 1, `d945600d060e` ([go.dev/issue/46289](https://go.dev/issue/46289), 2025-10-06); lesson: exit codes are API; note `-l` still exits 0 while listing files — do not copy that ambiguity into `--check`.

**Recurrence.** Comment handling dominates: ~7 real fixes, all downstream of the Go 1.19 doc-comment formatter, plus idempotence (one reverted fix; the corpus test still hard-codes a skip for `issue22662.go`, [go.dev/issue/24472](https://go.dev/issue/24472)), layout (4 fixes, one a libm dependency), invalid-or-changed output (3), and write-path safety (5, one a darwin-only data race). Crashes are rare but real. Property tests this argues for, in order: idempotence over every fixture and corpus file; re-parse equality; comment byte/multiset equality; platform-identical output; refusal-and-I/O-failure leaves the file untouched.

**Tests.** `src/go/printer/printer_test.go` runs `testdata/<name>.input` → `*.golden` pairs with mode bits, including `idempotent` (set for 17 of 22 entries: the golden is formatted again and must be byte-equal) and `rawFormat`/`normalizeNumbers` variants; `src/go/format` has no testdata and formats *its own source* (`TestSource`), pins that `Node` does not modify the AST (`TestNodeNoModify`) and that fragments (`""`, `" "`, comment-only) come back unchanged (`TestPartial`); `cmd/gofmt` `TestRewrite` runs each testdata pair **and `gofmt.go`/`gofmt_test.go` themselves**, then re-runs each golden to check idempotence; `TestDiff` pins the `-d` exit codes; `TestCRLF` asserts CR-free output; `gofmt_unix_test.go` covers permissions/mtime; `long_test.go` `TestAll` walks `$GOROOT`, formats twice, compares bytes — with the one hard-coded skip above. No fuzzing exists under `src/go/`. Licence: BSD-3-Clause.

**API and integrations.** `go/printer` exposes `Config{Mode, Tabwidth}` and `Fprint`; `Mode` bits include `RawFormat`, `SourcePos` and the unexported `normalizeNumbers` "specifically for go/format and cmd/gofmt"; `printer.CommentedNode` prints a node with its comment groups. `go/format.Source([]byte) ([]byte, error)` parses a file or fragment and sorts imports; `format.Node` prints an AST without modifying it. The CLI is `-l`, `-w`, `-d`, `-e`, `-r rule`, `-s`; no args reads stdin and accepts a fragment (`-w` with stdin is an error). Exit codes: 0 normally, 1 when `-d` found a difference, 2 on error — `-l` still exits 0 (the trap above). There is **no config file and no ignore pragma**: the only meaningful comments are build constraints, which gofmt *relocates*, and `//line` directives. `go fmt` is `gofmt -l -w` over a package's files. `go/format`'s own doc warns tools to "execute a specific version of the gofmt binary instead of using this package" because output changes between releases — the official position is pin the binary, not an option file. Most-requested features (open/closed issue pages copied 2026-10-09): versioned gofmts [#26397](https://github.com/golang/go/issues/26397) (closed, 17 reactions), the `-d` exit code [#46289](https://github.com/golang/go/issues/46289), CRLF preservation [#16355](https://github.com/golang/go/issues/16355) (24), comment preservation [#76975](https://github.com/golang/go/issues/76975) (18), blank-line policy [#6996](https://github.com/golang/go/issues/6996) (open, 17), import grouping [#37719](https://github.com/golang/go/issues/37719)/[#48552](https://github.com/golang/go/issues/48552).

**Ideas to migrate.** Idempotence as a property over every fixture and the corpus, failing rather than skipping (S) — gofmt still skips one known case. Comment multiset/byte equality after masking (S) — the check that would have caught three of the fixes above. A pinned real-HOCON corpus run that formats twice and prints the file (M). CLI script tests for `--check` exit codes, stdin, read-only and symlinked files (M). Platform-identical output over JVM/JS/Native bytes (M). Self-formatting test: repo HOCON examples must be fixed points (S). Never reflow or re-indent inside `"""` (S).

## rustfmt

**History: the ten fixes worth reading.**

- **Block doc-comment closer never converged in one pass** — trigger `/**First comment.` + `*/` in a module; `light_rewrite_comment` padded a leading `*` only when not at column 0, so pass 1 and pass 2 differed and `--check` kept failing; `44ca78d` ([rust-lang/rustfmt#7017](https://github.com/rust-lang/rustfmt/pull/7017), fixes [#6639](https://github.com/rust-lang/rustfmt/issues/6639), 2026-08-07/09-03); lesson: test idempotence by running the formatter twice over every fixture; derive delimiter alignment from the indent you will emit, never the input's column.
- **`use self;` deleted one `self` per run** — trigger `use self;` / `use self::self::self;`; `UseTree` normalization popped a trailing `self` before checking whether the new last segment was also `self`; `334670e` ([#6573](https://github.com/rust-lang/rustfmt/pull/6573), fixes [#6558](https://github.com/rust-lang/rustfmt/issues/6558), 2025-06-11); lesson: a normalizing rewrite must be its own fixed point; if the formatter cannot represent a construct, keep it rather than shortening it iteratively.
- **Commas appended to a where-clause comment until the file grew** — trigger `impl Tau where (): Clone //,`; the single-line where-clause path appended the suppressed separator after a trailing comment, producing `//,,,,,,,,,,,`; `8d2c415` (fixes [#5941](https://github.com/rust-lang/rustfmt/issues/5941), 2023-11-01); lesson: separators go outside comments, comment bytes are never edited, and a file that grows between passes is the loudest idempotence bug there is.
- **Comment duplicated in a parenthesized expression** — trigger `(` / `// note` / `#[allow(...)] 0` / `)`; the pre-comment span was built from `subexpr.span` (attributes excluded) instead of `span()`, so the attribute fell inside the "missing comment" span and was copied; `a1fabbf` ([#5913](https://github.com/rust-lang/rustfmt/pull/5913), fixes [#5871](https://github.com/rust-lang/rustfmt/issues/5871), 2023-09-20); lesson: spans used for comment recovery must cover the node's decorations; test comments between every pair of adjacent tokens.
- **`=>` inside a comment broke match formatting** — trigger `_ =>` / `// comment with =>` / `{ ... }`; `arrow_snippet.rfind("=>")` searched raw source and found the arrow inside the comment; `9580747` ([#6092](https://github.com/rust-lang/rustfmt/pull/6092), fixes [#5998](https://github.com/rust-lang/rustfmt/issues/5998), 2024-03-12); lesson: every structural scan over raw text (`=` before `{`, `include`, `+include`) must be comment- and string-aware, with a give-up path when it is not.
- **Panic while reporting an error on a wide non-ASCII line** — a `☃` line over `max_width` with `--error-on-unformatted`; the highlight range was computed in display widths and used as byte offsets, slicing mid-codepoint; `6d6cd71` ([#7029](https://github.com/rust-lang/rustfmt/pull/7029), fixes [#6850](https://github.com/rust-lang/rustfmt/issues/6850), 2026-08-14); lesson: diagnostics run exactly when the input is already unusual; never mix display columns and byte indices, and property-test the error path too.
- **Import sorting panicked because `Ord` was not a total order** — trigger a mixed raw-identifier/`_`-prefixed `use` list; the hand-written comparator was non-transitive and std's sort panicked; `777e25a` ([#6375](https://github.com/rust-lang/rustfmt/pull/6375), fixes [#6333](https://github.com/rust-lang/rustfmt/issues/6333), 2024-11-04); lesson: any ordering path needs antisymmetry/transitivity properties and a stable-order fallback; a comparator is a specification.
- **Panic when whitespace separated `macro_rules` and `!`** — trigger `macro_rules ! say_hello { ... }` (or a comment between them); `span_after(span, "macro_rules!")` assumed adjacency and reported "bad span"; `53bf773` ([#6990](https://github.com/rust-lang/rustfmt/pull/6990), fixes [#6985](https://github.com/rust-lang/rustfmt/issues/6985), 2026-07-28); lesson: token-pasting assumptions in masking/regex code must tolerate comments and arbitrary whitespace — HOCON's `include` recognition must not require adjacency either.
- **Inverted span when an inner attribute was re-parented** — trigger an inner attribute inside a loop inside a closure; a synthetic block pushed `last_pos` past the following statement and `push_rewrite` requested a backwards span; `7e56db3` ([#6978](https://github.com/rust-lang/rustfmt/pull/6978), fixes [#6209](https://github.com/rust-lang/rustfmt/issues/6209), 2026-07-27); lesson: comments/attributes stay attached to their node when it is wrapped in synthetic nodes; assert every emitted span is forward or refuse.
- **An empty file stopped being empty** — a zero-byte file gained `\n` from `append_newline`, so formatting created a diff and the next `--check` failed again; `5e73127` ([#6839](https://github.com/rust-lang/rustfmt/pull/6839), fixes [#5364](https://github.com/rust-lang/rustfmt/issues/5364), 2026-03-27), gated behind `StyleEdition::Edition2027` after one revert; lesson: empty and whitespace-only input gets an explicit tested policy, and changing it is a style-versioned change.

**Recurrence.** Comment mutation/duplication never stopped: `1dcdfb2` (2022, #5217), `38659ec` (2022, #5505), the three above, then `d43b34c`/`b47f06f`/`e325046`/`3297756` in 2026, plus CHANGELOG 1.11.0 entries for comment duplication and `cfg_attr` copying. Comment loss/conversion appears as CHANGELOG entries in 1.5.0 (#4909), 1.5.3 (#5320), 1.7.0 (#5533), 1.9.0 (#6465). Idempotence, crash/ICE and ordering recur in bursts; CRLF and width each broke repeatedly. Properties, in order of how often they broke: `format∘format == format` on every fixture and corpus file; comment text multiset byte-identical and comments attached to the same owner; output parses with the same semantics; comparators are total; no panic and no backwards span on any input; `--check` exits 0 exactly when output equals input.

**Tests.** Unit tests live beside the code; `tests/rustfmt` drives the CLI. The bulk is golden: `system_tests` formats every file under `tests/source/` and compares byte-for-byte with `tests/target/` (asserting at least 300 ran); `idempotence_tests` re-formats every `tests/target/` file and requires equality (at least 400); `self_tests` formats rustfmt's own sources and fails on any warning (lost comment, overflow, trailing whitespace); `warning_tests` snapshots diagnostics with insta (`tests/warning/source/lost_comment.rs` — "not formatted because a comment would be lost"); `configuration_snippet` formats code blocks embedded in `Configurations.md`. Fixtures carry a `// rustfmt-<key>: <value>` header and an optional `tests/config/<name>.toml`; `RUSTC_BLESS` rewrites targets; idempotence/self tests are nightly-gated. CI is a 6-target × {nightly, stable} matrix, plus `integration.yml` formatting named real crates (bitflags, log, mdbook, futures-rs, clippy, …) to prove builds survive, plus a manual `check_diff.yml` over ~27 pinned repositories. No fuzz target in the clone. Licence: MIT OR Apache-2.0.

**API and integrations.** The crate is `rustfmt-nightly`: build a `Config` (`from_toml_path`, `load_config`) and a `Session`, then `session.format(Input::File|Text) -> Result<FormatReport, ErrorKind>`; the report carries per-node `FormattingError`s and `has_*` predicates, and `emit_mode` selects files/stdout/coverage/checkstyle/json/diff/modified-lines. `ErrorKind::LostComment` ("not formatted because a comment would be lost", `src/lib.rs`) is the per-node version of our refusal: `recover_comment_removed` keeps the original snippet whenever a rewrite would change comment content. CLI: `--check`, `--emit`, `--config-path`, `--edition`, `--style-edition`, `-l/--files-with-diff`, `--print-config`, nightly `--file-lines`, `--error-on-unformatted`, `--skip-children`; exit 0 clean, 1 for `--check` diffs **and** parse/operational errors. Config `rustfmt.toml`/`.rustfmt.toml` searched upward; ~80 options, unstable ones need nightly plus `unstable_features`. Pragmas: `#[rustfmt::skip]`, `#[rustfmt::skip::macros(...)]`, `skip_macro_invocations`, `skip_children`, and gitignore-style `ignore` globs (still unstable). Stability is versioned by `style_edition` (2015/2018/2021/2024 stable, 2027 unstable); the README excludes comments from the stability promise and says bug fixes may change formatting. Integrations: `cargo fmt`, `rustfmt-format-diff` (formats only changed lines of a diff — the hook-shaped entry point), `git-rustfmt`, editors incl. rust-analyzer. Most-requested (open issues by reactions, page copied 2026-10-09): `imports_granularity` [#4991](https://github.com/rust-lang/rustfmt/issues/4991) (74), give-up instead of over-long lines [#3863](https://github.com/rust-lang/rustfmt/issues/3863) (60), format `Cargo.toml` [#4091](https://github.com/rust-lang/rustfmt/issues/4091) (45), layout discretion [#4306](https://github.com/rust-lang/rustfmt/issues/4306) (40), format macros [#8](https://github.com/rust-lang/rustfmt/issues/8) (34).

Diagnostics with source context: `path:line:col`, the offending line, a caret (S). Cross-runtime golden runs (M) — our three engines. Feature-gated fixtures so a corpus stays green visibly (S).

## clang-format

**History: the ten fixes worth reading** (PR/issue numbers are those in the commit bodies at the clone HEAD).

- **A comment's indent/scope was lost during alignment** — trigger a multi-line comment inside an aligned operand; "the information about the comment's scope could get lost", so alignment then mis-indented the comment lines; `a0aed334d4e` ([PR #195398](https://github.com/llvm/llvm-project/pull/195398), fixes #194717, 2026-05-08); lesson: a comment's location relative to tokens — not just its existence — is state to preserve or refuse on; property-test comment indent stability.
- **Trailing comments misclassified** — comments the tokenizer assigned to the wrong token (tests adapted from #196760); `bae9ddca423` ([PR #206393](https://github.com/llvm/llvm-project/pull/206393), fixes #196663, 2026-06-30); lesson: attachment rules need explicit tests at every boundary (after a value, after a separator, before `}`); a wrong attachment is how a comment later moves.
- **The alignment bookkeeping invariants broke in several places** — `AlignArrayOfStructures` with trailing comments and escaped newlines; code mutated `WhitespaceManager::Change::Spaces` without updating `StartOfTokenColumn`/`PreviousEndOfTokenColumn`, so alignment math used stale columns; `7ab2ff44d3b` ([PR #180305](https://github.com/llvm/llvm-project/pull/180305), fixes #138151/#85937/#53442, 2026-03-14); lesson: when several paths mutate one structure, funnel them through one helper and assert the derived invariants — our masked-text/segment bookkeeping deserves the same single-writer rule.
- **The formatter edited inside a `// clang-format off` region** — trigger `SeparateDefinitionBlocks` plus a disabled region; a blank line was inserted before the `// clang-format off` comment itself; `e6a049021d2` ([PR #201995](https://github.com/llvm/llvm-project/pull/201995), fixes #106983/#146317, 2026-06-16); lesson: a disabled region must be byte-identical to the input — and the boundary blank lines are exactly where the edits leak.
- **Newlines before `// clang-format on` were discarded** — blank lines before the re-enable pragma ignored by the scanner; `6978738e1ef` ([PR #218022](https://github.com/llvm/llvm-project/pull/218022), fixes #217872, 2026-08-22); lesson: both boundaries of a region need byte-exact tests — this class recurred four times.
- **Formatting a `#` in a macro body was not idempotent** — pass 1 changed token positions so pass 2 saw a different input; `54ca1c4212e` ([PR #118513](https://github.com/llvm/llvm-project/pull/118513), fixes #118334, 2024-12-10); lesson: idempotence is not a side effect of correctness; assert the fixed point per golden and keep the minimised failing input.
- **Ignored files were formatted to empty output** — a file matched by `.clang-format-ignore` under `-i` printed an empty buffer; the commit text: "Tools rely on the expectation that clang-format will output a formatted file. In the case of ignored files, the formatted file should just be the input file, untouched."; `ccc3e81c0cf` ([PR #170416](https://github.com/llvm/llvm-project/pull/170416), fixes #170407, 2026-05-04); lesson: the pass-through path is as dangerous as the format path — a skipped or refused file must be emitted byte-identical, never truncated.
- **`--dry-run` crashed or truncated on a NUL byte** — the buffer was copied as a NUL-terminated string and read past its end; `049700fcef8` ([PR #188631](https://github.com/llvm/llvm-project/pull/188631), fixes #188500, 2026-03-26); lesson: length-based, not terminator-based, byte handling, and the check/dry-run path needs the same fuzz coverage as the write path.
- **Include sorting rewrote commented-out code and line splices** — a commented-out `#include` block and includes split with `\` at end of line were treated as sortable declarations; `ceade83ad5f` ([PR #97787](https://github.com/llvm/llvm-project/pull/97787), fixes #97539, 2024-07-05) and `141c544c037` ([PR #120680](https://github.com/llvm/llvm-project/pull/120680), fixes #109864, 2024-12-24); lesson: an ordering feature must first prove it does not touch inactive text — and in HOCON include order and duplicate keys are semantic, so we should not sort at all.
- **Incomplete formatting returned exit 0** — the exit status never reflected `FormattingAttemptStatus.FormatComplete`; `--fail-on-incomplete-format` was added in 2024-03-21 (`a29e9e32c50`, [PR #84346](https://github.com/llvm/llvm-project/pull/84346)); lesson: "I could not format this" must be a distinct observable outcome with its own exit code — the distinction our `Verdict` already makes.
- **Alignment pushed lines past `ColumnLimit`** — the length was computed from the first line of a multi-line construct only; `ca69a8d2f40` ([PR #165627](https://github.com/llvm/llvm-project/pull/165627), 2025-11-03); lesson: width computations must measure the post-change text of every affected line — any future HOCON width check belongs on the final output, not on estimates.

**Recurrence.** Comment attachment/indentation/alignment is the most frequent class (ten commits since 2022 listed in the notes, including comment-above-directive and aligning-comments cases); disabled/off regions recurred four times; blank/empty-line policy recurred (`fbfc2d9bcd7` — `MaxEmptyLinesToKeep: 0` deleting a required separator, #206406, 2026-08-27); crashes on malformed input are a steady stream (twelve commits). Our refusal stance converts the crash class into a refusal, but the comment classes transfer directly. Properties: comment multiset, order and attachment unchanged; fixed point; `--check` reports its own output clean; disabled regions byte-identical; skipped/refused files emitted byte-identical; includes neither reordered nor duplicated.

**Tests.** ~45 gtest files under `clang/unittests/Format/`, with `FormatTest.cpp` a 987 KB monolith plus per-language and feature splits (`FormatTestComments.cpp`, `FormatTestRawStrings.cpp`, `SortIncludesTest.cpp`, `CleanupTest.cpp`, `FormatTestSelective.cpp`, …); a fuzzer lives at `clang/tools/clang-format/fuzzer/ClangFormatFuzzer.cpp`. The harness carries the idempotence contract: `FormatTestBase.h`'s `format()` asserts `Status.FormatComplete` unless told otherwise, and `verifyFormat` asserts the expected text equals the output, **then re-formats the expected text** ("Expected code is not stable") **and the scrambled variant** — so every one-argument `verifyFormat` is simultaneously a golden test, a format-twice test and a "format the messed-up text back to canonical form" test. `FormatTestUtils.h`'s `test::messUp` is the scramble oracle: outside comments, directives and `\`-splices it turns newlines into spaces, collapses space runs and re-inserts newlines only where comments/directives demand them. `verifyIncompleteFormat`, `verifyNoChange`, `verifyIndependentOfContext`, `verifyNoCrash` and `ReplacementCount` cover the other outcomes. LLVM's CI containers carry clang-format and git-clang-format, and the tree is expected to stay formatted, but an exact self-check job is unverified at this HEAD. **API and integrations.** `clang/include/clang/Format/Format.h`: `getStyle(StyleName, FileName, FallbackStyle, Code, DiagHandler) -> Expected<FormatStyle>`; `reformat(style, code, ranges, fileName, status) -> tooling::Replacements` filling `FormattingAttemptStatus.FormatComplete`; helpers `formatReplacements`, `cleanup`, `sortIncludes`, `fixNamespaceEndComments`, `separateDefinitionBlocks`, `configurationAsText`. The CLI is a thin wrapper: `-i`, `--dry-run/-n` (with `--Werror`, `--fail-on-incomplete-format`, `--error-limit`), `--lines`/`--offset`/`--length` (mutually exclusive — the tool errors out rather than guessing), `--style`, `--fallback-style` (`none` skips formatting), `--sort-includes`, `--assume-filename`, `--output-replacements-xml`, `--dump-config`, `--list-ignored`; exit 1 on style/config/IO errors, and `--fail-on-incomplete-format` exists because the tool used to "return exit code 0 on incomplete results" — the hole our `Verdict` closes. Config discovery: `.clang-format` in parent directories, `--style=file`, `fallback-style`, `InheritParentConfig` (accepts a directory); `.clang-format-ignore` supports globstar and later negated patterns, and ignored files now pass through untouched. Disabling is text-based: `// clang-format off/on` (also `/* */`), recognised by `switchesFormatting(const FormatToken&)`, with one-line and prefix forms (`OneLineFormatOffRegex`). Integrations: `git-clang-format` formats only changed lines (`--staged`, `--commit`, `--diffstat`, `--extensions`, binary from `clangformat.binary`); a pre-commit mode was added and a stale `.git/clang-format-index.lock` that "blocking all subsequent commits" was fixed in 2026-03-19 (`1c3c349cf8a`, [PR #187379](https://github.com/llvm/llvm-project/pull/187379)) — unique temp paths and no persistent lock for our hook; `clang-format-diff.py` for patch ranges; in-tree emacs/sublime/bbedit plugins; clangd reformats ranges through the same API. Style versioning: `BasedOnStyle` composes named styles and options are deprecated with a documented mapping (e.g. `DeriveLineEnding` + `UseCRLF` folded into a `LineEnding` enum, 2023-01-12, `e3eca335940`) — config upgrades are a first-class concern. Most-requested by commit evidence: `SortIncludes` is the standout pain source, accumulating options and bugfixes for seven years (natural sort, files-before-folders, ignore-extension, skip commented-out includes, skip line splices, don't sort for C#), then empty-line policy (`MaxEmptyLinesToKeep`, `KeepEmptyLines.*`) and `.clang-format-ignore` behaviour. The pattern is telling: an ordering feature needed years of exceptions to stop corrupting inactive text.

**Ideas to migrate.** Format-twice in every golden plus a `messUp`-style scramble oracle (S) — the scrambled direction catches attachment bugs our current properties would not. A comment-inventory property comparing text multiset, relative order *and* attachment, with boundary cases (S/M). A byte-identical skip/refuse path test (S): refused files emit the input untouched, never empty, and exit codes distinguish clean/would-change/refused. Pragma off/on with both boundaries tested with blank lines (M) — the two clang-format bugs above. NUL/CRLF/BOM/no-final-newline policy in one place, with the check path fuzzed too (S). Config with loud failure on unknown keys and deprecation mappings (M). Never sort includes or keys; if a sort ever ships, it is opt-in and refuses on comments, duplicates and splices (L as a feature, free as a rule).

## Ideas to migrate — ranked

Ordered by value for hocon-fmt first, then cost. S ≈ under a day; M ≈ a few days; L ≈ a week or more.

1. **Format-twice as a CI gate over every golden and every property run** (S). rustfmt asserts a minimum fixture count so the suite cannot shrink; ruff built a dedicated job; gofmt still skips one known case. We have idempotence in `HoconFormatterInvariantsSpec`, but a *count* and a CI-visible second pass over the corpus add the guard these five histories earned.
2. **Format-off / skip pragmas** (`# hocon-fmt: off/on`, `# hocon-fmt: skip`, unclosed off = EOF, skip = the logical line/field, region byte-identical) (M). Every configurable formatter ended up needing one; Black has 21 commits on `fmt: skip` alone. For us it also unblocks the files we refuse for sconfig defects (env overrides, `+=`, nested objects) without weakening the promise.
3. **Comment-multiset assertion, including duplicates** (S). Black's `34bfc69` shows loss checks do not see duplication; ruff's debug-only `assert_all_formatted` is the pattern.
4. **Parse-the-output equivalence with a written exceptions list** (M). ruff's `tests/normalizer.rs` is the model; ours would list blank-line loss, `//`→`#`, `:`→`=`, path flattening — making the known meaning-adjacent changes counted and reviewable instead of unmeasured.
5. **`--diff` output and a machine-readable summary** (S). CI annotations and PR comments without parsing stderr; Black writes `GITHUB_OUTPUT`, ruff 0.17 emits `github`/`json`.
6. **`version` in `.hocon-fmt.conf` with a mismatch refusal, plus a written style promise** (M). scalafmt's single most-valued design; our plugins and pre-commit hooks then agree on what "formatted" means.
7. **Exit-code contract as a set of kinds, tested by spawning the binary** (S). scalafmt's bitmask and its #5359 ("a single unparseable file suppresses results for every other file"); google-java-format shipped 0-on-usage-error for years.
8. **A CLI script-test suite in the gofmt style** (`--check` codes, stdin, read-only, symlink, refusal-vs-error) (M). Every write-path bug in these repos was caught end-to-end, not by unit tests.
9. **Refusal snapshots** (S). rustfmt snapshots warning text with insta; our refusal wording is currently asserted loosely, and a snapshot makes a wording change reviewable.
10. **A pinned real-HOCON corpus that formats twice and reports instability** (M/L). ruff's ecosystem runs and scalafmt's community suites; our `limitations.md` already has the Akka/Pekko/Play numbers to make it a gate.
11. **"Abandon, don't mangle" as a first-class outcome with source context** (S/M). google-java-format's `ce80f77`; our `Refusal` is close, but diagnostics with `path:line:col` and a caret are the missing part.
12. **Nightly deep property run with automatic issue filing** (M). Black's `fuzz.yml` with Hypothesmith; ours is `-Dhocon.properties=20000` plus a wider generator — the properties found four real defects already.
13. **Cross-runtime byte-identical goldens** (M). gofmt's libm-per-CPU story is the sharpest warning; our three engines are one product.
14. **Per-case options in the golden format and adversarial runs** (S/M). Black's `# flags:`/`# output` and its line-length-1/opposite-style runs; our options already change which sconfig defects appear.
15. **Partial/range formatting** (L). Black, ruff, scalafmt, google-java-format and clang-format all have one; for an editor story it is the missing piece, but it interacts badly with sconfig's whole-file parse — defer past the parser replacement.
