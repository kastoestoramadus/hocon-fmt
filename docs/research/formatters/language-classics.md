# Classic language formatters

Profiles of ten formatters whose problems hocon-fmt can learn from, researched 2026-10-09 by
opening issues, docs and changelogs (`gh search/view`, release notes, project docs); every issue
title is quoted as GitHub returns it and every URL was fetched. The lens: hocon-fmt refuses rather
than corrupts (a lost comment or include counts), is idempotent, ships `--check` and exit codes, and
must never write a broken file. Its known weak spots are upstream in sconfig: comments detached by
a blank line are dropped and refused, `//` becomes `#`, `:` becomes `=`, blank lines are not kept,
`include` needs masking, and env overrides or substitution cycles are refused as unstable.

How to read a bug line: description — "issue title" ([#N](url), state yyyy-mm-dd); … — tag. The date
is the day the issue was opened (the state is as of 2026-10-09); a timeline date says what it is.

## gofmt

**Tool** — Go's formatter, `cmd/gofmt`, in the Go repo (https://github.com/golang/go); it existed in
the earliest snapshots (source copyright 2009) and shipped with Go 1 (2012-03-28,
https://go.dev/blog/go1). Stance: one canonical, unconfigurable style — "never have a debate about
spacing or brace position ever again" (https://go.dev/blog/gofmt). Small tracker by design: 261
issues/PRs mention `cmd/gofmt` in the title, only a handful mention idempotence.

**Design choices that matter to us**
- Opinionated, no config file: flags are `-l -w -r -s -d -e`; `-tabs`/`-tabwidth` were removed in 2014 (https://github.com/golang/go/issues/7101; https://pkg.go.dev/cmd/gofmt).
- Comments are kept by position but *reformatted*: doc comments get list/link/heading normalisation since Go 1.19 (https://go.dev/doc/go1.19); `//go:build` is synced with `// +build` since 1.17 (https://go.dev/doc/go1.17).
- Blank lines act as alignment hints and mostly survive; leading/trailing blank lines in bodies are kept (https://github.com/golang/go/issues/6996, open 2013-12-21).
- Imports are sorted and merged inside blocks, and `-s` simplifies (https://github.com/golang/go/issues/4414, closed 2012-11-20).
- Line width: never wraps, no width flag exists, only alignment (https://github.com/golang/go/issues/4419, closed 2012-11-21).
- Parse errors refuse the file; the partial-program paths that strip comments are named as bugs (https://github.com/golang/go/issues/5551, closed 2013-05-24).
- No ignore pragmas; build constraints are honoured and rewritten (https://github.com/golang/go/issues/21337, closed 2017-08-08).
- Check mode: `-l` and `-d` exit 0 even with differences; changing this is a four-year-old open proposal (https://github.com/golang/go/issues/46289, closed 2021-05-20; https://github.com/golang/go/issues/76405, open 2025-11-21). stdin is formatted when no path is given (https://pkg.go.dev/cmd/gofmt).

**Bug classes**
- comment-movement: comments are rearranged inside argument and field lists — "cmd/gofmt: faulty comment re-arrangement in argument lists" ([#13113](https://github.com/golang/go/issues/13113), open 2015-10-30); "cmd/gofmt: a comment at the end of a line clings onto/prevents insertion of a newline before the next line" ([#22631](https://github.com/golang/go/issues/22631), open 2017-11-08).
- comment-loss: `-r` rewrites and partial input eat comments — "cmd/gofmt: rewrite might eat comments when given statement" ([#6099](https://github.com/golang/go/issues/6099), closed 2013-08-10); "go/format: Inconsistent behaviour against gofmt for partial Go programs, comments are stripped" ([#5551](https://github.com/golang/go/issues/5551), closed 2013-05-24).
- semantic-change: doc-comment prose is rewritten (smart quotes, dropped trailing newline) — "go/doc: reconsider comment rewrites of `''` to `”`" ([#54312](https://github.com/golang/go/issues/54312), closed 2022-08-06); "cmd/gofmt: don't rewrite into smart quotes" ([#76975](https://github.com/golang/go/issues/76975), closed 2025-12-23); "cmd/gofmt: trailing newline in comments is removed since 1.19" ([#54489](https://github.com/golang/go/issues/54489), open 2022-08-16).
- idempotence: a second pass changes comment layout — "cmd/gofmt: not idempotent for comments with leading space and lists" ([#73958](https://github.com/golang/go/issues/73958), open 2025-06-03); "cmd/gofmt: not idempotent on line with multiple comments" ([#24472](https://github.com/golang/go/issues/24472), open 2018-03-21); "cmd/gofmt: non-idempotent formatting of line comments" ([#13702](https://github.com/golang/go/issues/13702), closed 2015-12-21).
- comment-movement: a comment lands after the wrong construct — "cmd/gofmt: puts `else if` comments in wrong place" ([#20562](https://github.com/golang/go/issues/20562), open 2017-06-03); "cmd/gofmt: incorrect comment placement for a comment following a function" ([#4381](https://github.com/golang/go/issues/4381), closed 2012-11-13).
- line-width-layout: alignment is keyed on comments, line breaks and wide runes — "cmd/gofmt: empty line doesn't reset value alignment" ([#26352](https://github.com/golang/go/issues/26352), closed 2018-07-12); "cmd/gofmt: incorrect comment alignment with double-width runes" ([#7481](https://github.com/golang/go/issues/7481), closed 2014-03-06).
- partial-range: partial programs change raw string literal values or fail at EOF — "cmd/gofmt: applying gofmt to partial programs changes raw string literal values" ([#4449](https://github.com/golang/go/issues/4449), closed 2012-11-26); "cmd/gofmt: applying gofmt to partial code fails if it ends with line comment and no newline" ([#8411](https://github.com/golang/go/issues/8411), closed 2014-07-22).
- whitespace-eol-encoding: CRLF files are not honoured — "cmd/gofmt: doesn't honor line endings of Windows \r\n terminated source files" ([#16355](https://github.com/golang/go/issues/16355), closed 2016-07-13); "gofmt and gofix mangle line endings" ([#2242](https://github.com/golang/go/issues/2242), closed 2011-09-09).
- include-import-analog: build-constraint comments are moved or invented — "cmd/gofmt: honor build tags, especially release tags" ([#21337](https://github.com/golang/go/issues/21337), closed 2017-08-08); "`gofmt` automatically adding `go:build ` is annoying" ([#48383](https://github.com/golang/go/issues/48383), closed 2021-09-14).
- check-exit-codes: `-d`/`-l` report nothing to a CI script by exit code — "cmd/gofmt: change -d to exit 1 if diffs exist" ([#46289](https://github.com/golang/go/issues/46289), closed 2021-05-20); "proposal: cmd/gofmt: also exit 1 for `-l` (list paths)" ([#76405](https://github.com/golang/go/issues/76405), open 2025-11-21).
- crash: panics in the printer and rewrite path — "cmd/gofmt: panic from simple rewrite rule" ([#52145](https://github.com/golang/go/issues/52145), open 2022-04-04); "cmd/gofmt: don't panic when a rewrite would build a malformed AST" ([#81231](https://github.com/golang/go/issues/81231), open 2026-08-30).
- other: doc-comment list indentation is reflowed — "go/doc: improve headings, lists, and links" ([#51082](https://github.com/golang/go/issues/51082), closed 2022-02-08); "cmd/gofmt: indenting removed from multi-line bullet-lists inside numbered lists" ([#56072](https://github.com/golang/go/issues/56072), closed 2022-10-06).

**Relevance to hocon-fmt** — high: comment-loss, comment-movement, idempotence, semantic-change, whitespace-eol-encoding, include-import-analog, check-exit-codes, crash — each is a shipped promise of ours, and gofmt shows even a 2009-era printer still moves comments. Medium: partial-range (our stdin path resembles their partial programs), other (reflowing comment prose rewrites bytes that are not the formatter's), line-width-layout (layout churn, not correctness).

**Probe** — `a { b = 1 # note\n}\nc = 2 # after object`: both comments byte-identical and still on their lines after two passes. `a = 1  # one   # two` and `# - item\n#   cont`: `f(f(x)) == f(x)`. CRLF file: bytes preserved or refused, never converted. `include "base.conf" # note` under a licence banner: include, banner and note all survive in order. `--check` on `a: 1`: exit 1, zero bytes written.

**Development timeline** — 2009 gofmt exists in the first snapshots: style decided before any release, so migration debates never happened; 2012-03-28 Go 1 freezes it in every toolchain (https://go.dev/blog/go1); 2014 `-tabs`/`-tabwidth` removed (https://github.com/golang/go/issues/7101), the last style knob; 2016-07-13 CRLF handling closed without a fix ([#16355](https://github.com/golang/go/issues/16355)) — Windows users keep mangled files; 2021-09-14 Go 1.17 makes gofmt rewrite `//go:build` (https://go.dev/doc/go1.17); 2022-08-16 Go 1.19's doc reflow ([#54312](https://github.com/golang/go/issues/54312), 47 comments) is the pain users still report; 2025-10-08 the `-d` exit-code PR is closed unmerged ([#75649](https://github.com/golang/go/pull/75649)), leaving check mode unsolved after four years. **Ideas to migrate** — write the `--check` exit-code contract down and test it (S, high; #46289/#76405); a comment-placement corpus asserted as a property, not examples (M, high); explicit CRLF/encoding policy, preserve or refuse, tested on every platform (M, medium).

## rustfmt

**Tool** — Rust's formatter, in https://github.com/rust-lang/rustfmt; 0.0.1 on crates.io 2015-01-13 (https://crates.io/api/v1/crates/rustfmt/versions), 1.0.0 on 2018-11-19 (https://github.com/rust-lang/rustfmt/blob/master/CHANGELOG.md). Stance: the default output is the official Rust Style Guide (https://github.com/rust-lang/rfcs/blob/master/text/2436-style-guide.md) and users are urged not to configure it, yet "Rustfmt is designed to be very configurable" (https://github.com/rust-lang/rustfmt/blob/master/Configurations.md) — a tension the tracker reflects: ~130 items with "comment" in the title, ~106 mentioning idempotence.

**Design choices that matter to us**
- Configurable where gofmt is not: `rustfmt.toml`/`.rustfmt.toml`, with stable and nightly-only unstable options gated by `unstable_features = true` (https://github.com/rust-lang/rustfmt/blob/master/Configurations.md).
- Comments follow position and move or vanish in known cases; `normalize_comments` and `wrap_comments` are opt-in and off by default (https://github.com/rust-lang/rustfmt/blob/master/Configurations.md).
- Blank lines: `blank_lines_upper_bound` defaults to 1, so extra blanks are trimmed (https://github.com/rust-lang/rustfmt/issues/3928, closed 2019-11-15).
- Ordering: `reorder_imports` defaults on; `group_imports` has been unstable since it landed (https://github.com/rust-lang/rustfmt/issues/5083, open 2021-11-14).
- Line width `max_width` defaults to 100, but long strings/idents make it give up rather than overflow (https://github.com/rust-lang/rustfmt/blob/master/Configurations.md; https://github.com/rust-lang/rustfmt/issues/6338, open 2024-09-19).
- Parse errors refuse the file, but the stability guarantee explicitly excludes code that fails to parse (README "Limitations"), which is where its corruption bugs live.
- Ignore pragmas are layered: `#[rustfmt::skip]`, `rustfmt::skip::macros`/`::attributes` (https://github.com/rust-lang/rustfmt/pull/3454, merged 2019-03-24), module-level skip (https://github.com/rust-lang/rustfmt/pull/5094, merged 2021-12-08).
- Ranges: `--file-lines` is nightly-only and repeatedly leaked outside the range (https://github.com/rust-lang/rustfmt/issues/5136, closed 2021-12-13; https://github.com/rust-lang/rustfmt/issues/6863, closed 2026-04-15).
- Check: `--check` exits non-zero on a diff (README); stdin loses config unless `--assume-filename` is given (https://github.com/rust-lang/rustfmt/issues/2668, closed 2018-04-30).

**Bug classes**
- comment-loss: comments disappear from lists and uses — "Rustfmt silently removes comments after enum/struct field" ([#5464](https://github.com/rust-lang/rustfmt/issues/5464), open 2022-07-24); "rustfmt deletes comments in "or" patterns" ([#6044](https://github.com/rust-lang/rustfmt/issues/6044), open 2024-01-26); "Rustfmt removes comments in `use`s" ([#3984](https://github.com/rust-lang/rustfmt/issues/3984), closed 2019-12-26).
- comment-movement: trailing comments land on unrelated code — "rustfmt forcefully moves trailing comments to irrelevant code above (and not idempotent either)" ([#6347](https://github.com/rust-lang/rustfmt/issues/6347), open 2024-09-23); "Rustfmt puts single-line comment after wrong import when reordering imports" ([#4027](https://github.com/rust-lang/rustfmt/issues/4027), closed 2020-01-24).
- idempotence: two passes are needed on macros, strings and imports — "Non-idempotency involving return expr in match arm, macros and long string literals" ([#6613](https://github.com/rust-lang/rustfmt/issues/6613), open 2025-07-23); "rustfmt requires two runs to converge on contrived input" ([#6437](https://github.com/rust-lang/rustfmt/issues/6437), open 2025-01-06); "Group imports together with imports_granularity results in non-idempotent formatting" ([#6195](https://github.com/rust-lang/rustfmt/issues/6195), open 2024-06-14).
- semantic-change: macro tokens are deleted, output stops compiling — "rustfmt emits non-compiling code by removing tokens from function-like macro invocations" ([#7021](https://github.com/rust-lang/rustfmt/issues/7021), closed 2026-08-10); "rustfmt removes crucial code from macro calls (regression)" ([#6424](https://github.com/rust-lang/rustfmt/issues/6424), closed 2024-12-22).
- semantic-change: meaning changes without macros — "rustfmt joins numbers separated by dot and whitespace" ([#4807](https://github.com/rust-lang/rustfmt/issues/4807), closed 2021-04-21); "Rustfmt changes meaning of closure, also not idempotent" ([#4050](https://github.com/rust-lang/rustfmt/issues/4050), open 2020-02-12).
- embedded-language: whitespace is injected into string literals inside macros — "Rustfmt incorrectly adds whitespace inside multiline string literals within macro calls that have curly braces" ([#5283](https://github.com/rust-lang/rustfmt/issues/5283), open 2022-03-31); "rustfmt thinks it should be able to modify string values" ([#5744](https://github.com/rust-lang/rustfmt/issues/5744), closed 2023-04-08).
- parse-error-handling: lines are deleted instead of reporting a syntax error — "rustfmt deletes lines instead of detecting a syntax error" ([#4126](https://github.com/rust-lang/rustfmt/issues/4126), closed 2020-04-18); "Rustfmt command returns an error despite problematic file being ignored and hide_parse_errors is true" ([#3916](https://github.com/rust-lang/rustfmt/issues/3916), closed 2019-11-09).
- whitespace-eol-encoding: trailing whitespace becomes a hard failure — "rustfmt fails with errors "left behind trailing whitespace"" ([#2896](https://github.com/rust-lang/rustfmt/issues/2896), closed 2018-08-04); "Trailing whitespace in macro causes rustfmt exit code 1" ([#6479](https://github.com/rust-lang/rustfmt/issues/6479), closed 2025-02-18).
- line-width-layout: `max_width` reflows lines that fit — "max_width makes short lines longer" ([#6338](https://github.com/rust-lang/rustfmt/issues/6338), open 2024-09-19); "Rustfmt breaks chained method calls that are below max_width" ([#3784](https://github.com/rust-lang/rustfmt/issues/3784), closed 2019-09-06).
- ordering: import reordering deletes tokens — "rustfmt eats _ in underscore_imports (a.k.a. impl-only-use)" ([#2887](https://github.com/rust-lang/rustfmt/issues/2887), closed 2018-08-02); "`use self;` gets entirely deleted" ([#6558](https://github.com/rust-lang/rustfmt/issues/6558), closed 2025-05-09).
- config-ignore: skip pragmas half-work or output vanishes — "`rustfmt::skip` sometimes ignored when using `error_on_line_overflow` and `error_on_unformatted`" ([#6954](https://github.com/rust-lang/rustfmt/issues/6954), open 2026-06-26); "In some cases rustfmt emits nothing on files with `#![cfg_attr(rustfmt, rustfmt_skip)]` when using `--emit=stdout`" ([#5519](https://github.com/rust-lang/rustfmt/issues/5519), closed 2022-08-27); "rustfmt using input from stdin emits empty output when using `#![rustfmt::skip]`" ([#5368](https://github.com/rust-lang/rustfmt/issues/5368), closed 2022-06-04).
- partial-range: `--file-lines` changes whitespace outside the range — "file-lines changes whitespace outside of given range" ([#5136](https://github.com/rust-lang/rustfmt/issues/5136), closed 2021-12-13); "file-lines can modify lines above the selected range" ([#6863](https://github.com/rust-lang/rustfmt/issues/6863), closed 2026-04-15).
- config-ignore: config discovery surprises (stdin, macOS, subdirectories) — "rustfmt skips rustfmt.toml if using stdin" ([#2668](https://github.com/rust-lang/rustfmt/issues/2668), closed 2018-04-30); "Config in `rustfmt.toml` completely ignored on macOS" ([#6068](https://github.com/rust-lang/rustfmt/issues/6068), closed 2024-02-09); "`cargo fmt` ignores `rustfmt.toml` in subdirectory" ([#5814](https://github.com/rust-lang/rustfmt/issues/5814), closed 2023-07-05).
- check-exit-codes: `--check` is wrong on edge inputs — "rustfmt fails on an empty file; --check's diff doesn't result in properly formatted file" ([#5364](https://github.com/rust-lang/rustfmt/issues/5364), open 2022-06-02); "rustfmt --check reports success with input piped from stdin" ([#6789](https://github.com/rust-lang/rustfmt/issues/6789), closed 2026-02-03).
- crash: unwrap-driven panics and segfaults — "rustfmt panic / in unwrap() we trust / good first issue" ([#7158](https://github.com/rust-lang/rustfmt/issues/7158), open 2026-10-04); "Error running rustfmt: Segmentation fault (core dumped)" ([#5126](https://github.com/rust-lang/rustfmt/issues/5126), closed 2021-12-05).

**Relevance to hocon-fmt** — high: comment-loss, comment-movement, idempotence, semantic-change, embedded-language, parse-error-handling, whitespace-eol-encoding, config-ignore, check-exit-codes, crash — comments are payload, includes are directives, a second pass must not move bytes, and strings and substitutions are opaque (their macro bugs are our `"""` and `${?ENV}`). Medium: partial-range (no range mode yet; #6863 would be the spec), ordering (include order is semantic; #2887 shows reorders delete tokens), line-width-layout. Low: performance.

**Probe** — `a { b = 1 # note\n}` and `x = [1, # one\n 2]`: every comment present exactly once in the *text*, not just the parse. `a = "x // y"`, `b = """line # not comment"""`, `c = ${?ENV}`: bytes unchanged after masking round-trip. `# hocon-fmt: off` is not implemented — assert an unknown directive is either honoured or preserved verbatim, never half-applied. Unclosed `a { b = 1\n# trailing`: refusal, file untouched, comment still there. `--check` on a refused file: reported as refused, not as unformatted, and no write.

**Development timeline** — 2015-01-13 0.0.1 makes the tool configurable from day one, the option surface becoming the maintenance drag (https://crates.io/api/v1/crates/rustfmt/versions); 2018-11-19 1.0.0 starts the stability promise but carves out code that fails to parse, where the corruption bugs live (https://github.com/rust-lang/rustfmt/blob/master/CHANGELOG.md); 2019-03-24 `rustfmt::skip::macros` lands because macro formatting is unsafe (https://github.com/rust-lang/rustfmt/pull/3454) — and still is ([#7021](https://github.com/rust-lang/rustfmt/issues/7021), 2026-08-10); 2020-06-29 the version/style-edition strategy is settled ([#4286](https://github.com/rust-lang/rustfmt/issues/4286), closed 2020-06-29); 2021-11-14 `group_imports` stays nightly-only after 27 comments ([#5083](https://github.com/rust-lang/rustfmt/issues/5083)); 2026-02-26 1.9.0 announces `style_edition = "2024"`, so upgrades can change layout only behind an edition (CHANGELOG); 2026-10-04 a new panic is filed ([#7158](https://github.com/rust-lang/rustfmt/issues/7158)). **Ideas to migrate** — idempotence and comment preservation as property tests over generated HOCON, not examples (M, high); never emit empty or partial output, assert output sanity and refuse on internal failure (S, high; #5519/#5368); one stated config-discovery rule, no home fallback unless asked (M, medium; #2668/#6068); if a skip pragma ever lands, implement it fully or not at all (M, medium).

## black

**Tool** — Python's opinionated formatter, https://github.com/psf/black; 18.3a0 on 2018-03-14, "first published version, Happy 🍰 Day 2018!" (https://github.com/psf/black/blob/main/CHANGES.md; https://pypi.org/pypi/black/json). Stance: "style configuration options are deliberately limited and rarely added" (https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html).

**Design choices that matter to us**
- Opinionated by default: line length, target version and a few adoption helpers only; a yearly "stable style" release is the one deliberate break (https://black.readthedocs.io/en/stable/the_black_code_style/index.html).
- Line width defaults to 88 ("10% over 80") and Black may exceed it rather than break another rule (https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html).
- Comments: contents never reformatted, spacing normalised; "Comments may sometimes be moved… which can break tools that assign special meaning to them" — the noqa/tool-directive trap (https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html).
- Blank lines: spurious vertical whitespace removed, blanks inside parenthesised expressions are lost (https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html).
- Import ordering is deliberately out of scope, which causes churn with reorder tools (https://github.com/psf/black/issues/333, closed 2018-06-10; https://github.com/psf/black/issues/4175, closed 2024-01-26).
- Parse errors refuse the file: "error: cannot parse", reported, never written (https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html).
- Pragmas: `# fmt: on/off` must sit at the same indentation and in the same block; `# fmt: skip` suppresses one line (https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html).
- Magic trailing comma: an existing trailing comma forces one item per line; removing it lets the formatter collapse the construct (https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html).
- Safety: `--safe` (default) compares source and output ASTs; `--fast` disables it, and three AST-visible cases are known (docstrings, `del` parens, moved comments) (https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html).
- Check: exit 0 nothing, 1 would reformat, 123 internal error; `--line-ranges` is 1-based inclusive and not allowed in pyproject; stdin is `-` with `--stdin-filename` (https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html).
- Config discovery: from the common base directory of the arguments upwards, stopping at pyproject.toml, `.git`/`.hg` or root, one file per run (https://black.readthedocs.io/en/stable/usage_and_configuration/the_basics.html).

**Bug classes**
- comment-loss: `# fmt: skip` deleted a comment-only line before it — "fmt: skip removes a comment-only line before it" ([#2339](https://github.com/psf/black/issues/2339), closed 2021-06-17); "Commented strings" ([#2441](https://github.com/psf/black/issues/2441), closed 2021-08-24). The stability policy itself admits "we have had bugs where we accidentally removed some comments" (https://black.readthedocs.io/en/stable/the_black_code_style/index.html).
- comment-movement: comments are re-anchored where a tool no longer sees them — "flake8 #noqa comments get moved a place where they're ignored" ([#195](https://github.com/psf/black/issues/195), closed 2018-05-08); "Option to ignore in-line comments" ([#3450](https://github.com/psf/black/issues/3450), closed 2022-12-18).
- idempotence: a second pass produced different code; in 2026 the same AST still had two stable states — "INTERNAL ERROR: Black produced different code on the second pass of the formatter" ([#1629](https://github.com/psf/black/issues/1629), closed 2020-08-26); "Consecutive @overload definitions have two distinct stable formatting states for the same AST" ([#5001](https://github.com/psf/black/issues/5001), closed 2026-02-22).
- semantic-change: `# fmt: skip` dropped a comma and turned a tuple into a call; attribute-chain flattening merged two `# type: ignore` comments — "Fix fmt: skip turning a bracketed ternary into a call" ([#5464](https://github.com/psf/black/pull/5464), merged 2026-10-01); "Preserve type ignores in attribute chains" ([#5297](https://github.com/psf/black/issues/5297), merged 2026-08-07).
- parse-error-handling: valid-looking input failed outright — "Black fails when comment exists inside of list comprehension" ([#563](https://github.com/psf/black/issues/563), closed 2018-10-15); "Black fails to tokenise files ending with a backslash" ([#1012](https://github.com/psf/black/issues/1012), closed 2019-09-10).
- crash: internal errors found by fuzzing — "Fix Bug exposed by Fuzz Tests" ([#1913](https://github.com/psf/black/issues/1913), closed 2021-01-08); "internal error while formatting with-statement with tuple and none tuple argument" ([#4642](https://github.com/psf/black/issues/4642), closed 2025-04-02).
- whitespace-eol-encoding: tabs are refused rather than formatted, and empty-line rules were inconsistent — "Tab Support Request" ([#2798](https://github.com/psf/black/issues/2798), closed 2022-01-22); "Black is inconsistent with empty lines before an inner function after code block open, with or without leading comments" ([#3300](https://github.com/psf/black/issues/3300), closed 2022-09-29).
- line-width-layout: long strings and the magic comma each took years to settle — "feature_request(formatting): wrap long strings" ([#182](https://github.com/psf/black/issues/182), closed 2018-04-30); "Finish "magic trailing comma" handling" ([#1288](https://github.com/psf/black/issues/1288), closed 2020-03-03).
- partial-range: `--line-ranges` leaked outside the selection, and one run poisoned the cache — "`--line-ranges` formats lines outside of range" ([#4430](https://github.com/psf/black/issues/4430), closed 2024-08-06); "Empty new line added after docstring when using `--line-ranges`" ([#5285](https://github.com/psf/black/issues/5285), closed 2026-07-31); "`--line-ranges` fails to parse when an @overload function is inside a class" ([#4818](https://github.com/psf/black/issues/4818), closed 2025-10-30).
- check-exit-codes: `--check` reported success on a file a range run had left unformatted — "Check passes on unformatted file after running with line ranges" ([#5474](https://github.com/psf/black/issues/5474), closed 2026-10-03); the fix is "Fix check passing after a line ranges run" ([#5476](https://github.com/psf/black/pull/5476), merged 2026-10-05).
- config-ignore: a file was silently unformatted when cwd was under a symlinked parent — "`black` ignores file in current folder if current folder is `git` workspace and (parent of) current folder is a symbolic link" ([#4205](https://github.com/psf/black/issues/4205), closed 2024-02-02); "Can we add a json schema to complete pyproject.toml's `[tool.black]`?" ([#4160](https://github.com/psf/black/issues/4160), closed 2024-01-20).
- ordering: imports stay untouched by design, so users fight over it — "[Feature Request] Optimize imports" ([#333](https://github.com/psf/black/issues/333), closed 2018-06-10); "Unexpected incompatibility with reorder-python-imports" ([#4175](https://github.com/psf/black/issues/4175), closed 2024-01-26).
- other: the yearly stable style is the main churn source; within a year formatted code is guaranteed unchanged — "Setting the 2024 stable style" ([#4042](https://github.com/psf/black/issues/4042), closed 2023-11-13); "Setting the 2023 stable style" ([#3407](https://github.com/psf/black/issues/3407), closed 2022-12-09).

**Relevance to hocon-fmt** — high: comment-loss and comment-movement (Black's own policy admits lost comments; the noqa move is our include-and-its-note case), idempotence (pre-commit reruns; #5001 shows a "stable" second state can still exist), semantic-change (their tuple/call bug is our quoting or include drop), parse-error-handling and crash (refuse, never write), check-exit-codes (a wrong 0 erodes trust fastest). Medium: whitespace-eol-encoding (our BOM/CRLF policy is a normalisation today), line-width-layout (magic-comma-style intent signals), config-ignore (one config, stated discovery), other (a written stability policy is cheap). Low: partial-range (editor-only feature), ordering.

**Probe** — `a { # keep\n  b = 1  # inline\n}`: both comments byte-identical and `--check` clean after formatting. `# rationale\ninclude "x.conf"\ninclude "y.conf"  # note`: no comment crosses an include boundary. Nested objects with substitutions and comments, formatted twice: second output byte-identical. `a = "1"`, `a = ${?X}`, `a = [1] [2]`, `a = 3s`: no unquoting, no concatenation folding. `a = {` and an unterminated string: refusal, distinct non-zero code, no write. Empty file, BOM, CRLF-only, 1000-level nesting: clean exit, no write.

**Development timeline** — 2018-03-14 18.3a0 first release, with `--check` a day-one product requirement (CHANGES.md, PyPI JSON); 2019-05-06 the request to format a selection ([#830](https://github.com/psf/black/issues/830)) lands as `--line-ranges` only in 23.11.0, 2023-11-08; 2024-01-26 24.1.0 ships the 2024 stable style ([#4042](https://github.com/psf/black/issues/4042)), annual churn users must absorb; 2025-01-29 25.1.0 and 2026-01-18 26.1.0 follow the same cadence; 2026-10-04 26.10.0 fixes more fmt:skip and line-range bugs, and five further range fixes are unreleased — ranges are still the bleeding edge (CHANGES.md). **Ideas to migrate** — the runtime output-safety check (parse the output, compare meaning, re-format and compare) is already our pipeline; document it as a contract (S, high); exit-code contract 0/1/2 with "would reformat" on stderr, pinned by tests (S, high); `# hocon-fmt: off/on/skip` with the same-block rule (M, high); a written stability policy for hook users (S, high); fuzzing as a standing job (M, high; #1913/#1960 found real crashes).

## ruff format

**Tool** — Ruff's formatter, Rust, in the linter's repo https://github.com/astral-sh/ruff; earliest release 0.0.13 on 2022-08-27, formatter announced with 0.1.0 on 2023-10-16 (https://pypi.org/pypi/ruff/json; https://astral.sh/blog/ruff-v0.1.0). Stance: "an extremely fast Python code formatter designed as a drop-in replacement for Black", matching >99.9% of lines with deviations documented (https://docs.astral.sh/ruff/formatter/).

**Design choices that matter to us**
- Opinionated but more knobs than Black: line length 88 (same default), indent width, quote/indent style, docstring-code options (https://github.com/astral-sh/ruff/blob/main/docs/configuration.md).
- Comments: pragma comments (`# type`, `# noqa`, `# pyright`) are excluded from line-width so they are not moved; where Black would move an end-of-line comment, Ruff expands rather than collapses (https://docs.astral.sh/ruff/formatter/black/).
- Blank lines: does not allow a blank line at the start of a block, a deliberate deviation from Black (https://docs.astral.sh/ruff/formatter/black/).
- Import sorting is a separate rule set (`I`, isort-like), never part of `ruff format` — the split is deliberate (https://github.com/astral-sh/ruff/issues/465, closed 2022-10-25).
- Parse errors abort: abnormal termination is exit 2 and the file is not written (https://docs.astral.sh/ruff/formatter/).
- Pragmas: `# fmt: on/off/skip` at statement level; `# fmt: skip` inside an expression does nothing; Markdown uses HTML `<!-- fmt: off -->` (https://docs.astral.sh/ruff/formatter/).
- No runtime AST-equivalence check; stability is enforced in fixtures and by formatting real projects, erroring on invalid output, comment loss or instability (https://github.com/astral-sh/ruff/issues/8184, closed 2023-11-13).
- Check: `ruff format --check` exits 0 clean, 1 would change, 2 abnormal; `--exit-non-zero-on-format` covers write mode; stdin is `-` with `--stdin-filename` (https://docs.astral.sh/ruff/formatter/).
- Config discovery is per file: nearest pyproject.toml/ruff.toml wins, CLI overrides all (https://github.com/astral-sh/ruff/blob/main/docs/configuration.md).
- Preview: risky style changes land behind `preview` and are promoted through minors; semantic and comment fixes ship as patches (https://docs.astral.sh/ruff/versioning/).

- comment-loss: trailing `elif` comments disappeared — "Formatter: Trailing elif comments disappear" ([#5086](https://github.com/astral-sh/ruff/issues/5086), closed 2023-06-14); "bug: lost comments during autofix" ([#3185](https://github.com/astral-sh/ruff/issues/3185), closed 2023-02-23).

- line-width-layout: method-chain layout was a long design fight — "ruff formatter: one call per line for chained method calls" ([#8598](https://github.com/astral-sh/ruff/issues/8598), closed 2023-11-10); "Allow newlines after block open (or not)" ([#9745](https://github.com/astral-sh/ruff/issues/9745), closed 2024-01-31).

- embedded-language: formatting Markdown code blocks and docstring code examples, opt-in and late — "Apply `ruff` formatting to `markdown` code blocks" ([#3792](https://github.com/astral-sh/ruff/issues/3792), closed 2023-03-29); "Using ruff to format code examples in docstrings" ([#7146](https://github.com/astral-sh/ruff/issues/7146), closed 2023-09-05).
- performance: speed is the product; the parser was chosen for it and autoformat was a years-long epic — "Explore alternatives to RustPython for Python AST parsing" ([#286](https://github.com/astral-sh/ruff/issues/286), closed 2022-09-29); "Implement autoformat capabilities" ([#1904](https://github.com/astral-sh/ruff/issues/1904), closed 2023-01-16).
- other: suppression blocks took about three years, and Black compatibility is a tracked ledger of deliberate deviations — "[feature request] Support ignore block of code with noqa" ([#3711](https://github.com/astral-sh/ruff/issues/3711), closed 2023-03-24); "📋 Formatter black compatibility tracking issue" ([#5828](https://github.com/astral-sh/ruff/issues/5828), closed 2023-07-17).
- check-exit-codes: the documented contract is 0/1/2 (https://docs.astral.sh/ruff/formatter/), but exit codes still blur together — "`ruff format --check` uses same exit code for syntax errors in files, and usage errors" ([#27602](https://github.com/astral-sh/ruff/issues/27602), open 2026-08-08); "ruff with `--diff` exits 0 on errors with no diffs" ([#11955](https://github.com/astral-sh/ruff/issues/11955), open 2024-06-20).

**Relevance to hocon-fmt** — high: comment-loss, comment-movement, idempotence, semantic-change, parse-error-handling, crash, include-import-analog, check-exit-codes. Ruff's rule that a fix able to drop a comment must be unsafe or rejected is exactly our include-masking rationale, and #28416 is the cautionary tale for any pass that reorders while carrying pragmas. Medium: config-ignore (their per-file nearest config is more magic than our lookup needs), line-width-layout (design fights consume years), other (preview gating and a limitations ledger). Low: performance, embedded-language.

**Probe** — `[1, # one\n 2]`: inline comment and its line association survive; `include "x.conf"  # why`: no migration across the include; formatted fixture twice: byte-identical; `a = "1"`, `a = ${?X}`, `x = ${a}${b}`: quoting and concatenation preserved; unparseable `a = "unterminated`: exit distinct from "would reformat", no write, no crash; `include required(classpath("x"))` with no file on disk: include kept, nothing resolved.

**Development timeline** — 2022-08-27 0.0.13 the linter alone; 2022-10-25 import sorting is proposed as a separate rule set ([#465](https://github.com/astral-sh/ruff/issues/465)), the split that still bites; 2023-10-16 0.1.0 brings `ruff format` to users with the autoformat epic closed ([#1904](https://github.com/astral-sh/ruff/issues/1904)); 2023-11-13 the no-runtime-AST-check decision is recorded ([#8184](https://github.com/astral-sh/ruff/issues/8184)); 2024-02-02 the comment-loss policy makes "never lose comments" explicit ([#9790](https://github.com/astral-sh/ruff/issues/9790)); 2025-01-09 0.9.0 stabilises f-string formatting, a documented deviation from Black; 2026-01-16 `# noqa` ignore blocks land ([#3711](https://github.com/astral-sh/ruff/issues/3711)) and 2026-03-05 Markdown code blocks follow ([#3792](https://github.com/astral-sh/ruff/issues/3792)); 2026-10-01 0.16.10 keeps the near-weekly cadence. **Ideas to migrate** — exclude pragma comments from any width logic so they are never moved (M, high); a test-suite stability contract: format twice, compare, and fail on comment-count or would-reformat drift (S, high); an unsafe tier for anything that can drop a comment, blocked by default (M, high); distinct exit codes with abnormal termination separate (S, high); preview gating for layout changes (S, medium).

## scalafmt

**Tool** — Scala's formatter (scalameta parser), https://github.com/scalameta/scalafmt; v0.1.0-RC2 on 2016-03-03 (https://github.com/scalameta/scalafmt/releases/tag/v0.1.0-RC2); v3.11.5 on 2026-07-27. Our ecosystem's sibling: the same shape of tool, same build-tool integrations, same pinned style. Stance: opinionated defaults (`maxColumn = 80`) with an escape hatch for nearly everything, but projects must "agree on the standards" first and pin `version` plus `runner.dialect` (https://scalameta.org/scalafmt/docs/gotchas.html; https://scalameta.org/scalafmt/docs/configuration.html).

**Design choices that matter to us**
- Opinionated but configurable: default 2-space indent and 80 columns, every deviation a setting; docs warn `maxColumn` mismatches between tools are "a source of issues" (https://scalameta.org/scalafmt/docs/configuration.html).
- Reproducibility is explicit: since v3.1.0 a missing `version` or `runner.dialect` returns the file unchanged with an error (https://scalameta.org/scalafmt/docs/installation.html).
- Discovery: `.scalafmt.conf` from cwd, else the git root, else the default style; `--config`/`--config-str` override (https://scalameta.org/scalafmt/docs/installation.html).
- Ignore pragmas: `// format: off`/`on` (tags configurable since v3.8.4) and per-region `// scalafmt: {...}` comments, promoted to global config at the top of a file since v3.10.4 (https://scalameta.org/scalafmt/docs/configuration.html).
- Comments: untouched by default (`comments.wrap = no`), but the imports rewrite deliberately moves attached comments and can drop `/* */` ones (https://scalameta.org/scalafmt/docs/configuration.html).
- Blank lines: preserved, but they end alignment blocks and are configurable (`newlines.topLevelStatementBlankLines`, `newlines.source`) (https://scalameta.org/scalafmt/docs/configuration.html).
- No line-range formatting; selection is git-scoped (`--mode diff-ref=`, `changed`, `project.git = true`) and ratcheting for line ranges was closed unimplemented (https://github.com/scalameta/scalafmt/issues/1120, closed 2018-03-12; https://github.com/scalameta/scalafmt/issues/3344, closed 2022-10-11).
- Check: `--test` exits 1 on a mis-formatted file, `--check` exits 1 on the first failure, `--reportError`, `--list`, `onTestFailure`; checking never writes (https://scalameta.org/scalafmt/docs/installation.html).
- Failure model: on "Search state exploded" it bails, leaves the file unformatted and names the line; `encoding` and `lineEndings` (`unix` default, `preserve`) tune bytes (https://scalameta.org/scalafmt/docs/known-issues.html). stdin: `--stdin` with `--assume-filename`.

**Bug classes**
- comment-loss: a comment adjacent to rewritten tokens corrupts code — "[bug] formatting with comment on the same line breaks the code" ([#1325](https://github.com/scalameta/scalafmt/issues/1325), closed 2018-12-13); "Removing trailing comma also removes closing parens when next line starts directly with a comment" ([#1228](https://github.com/scalameta/scalafmt/issues/1228), closed 2018-06-28).
- comment-movement: import rewrites move or drop attached comments — "formatting fails when adding import in a class with javadocs" ([#2297](https://github.com/scalameta/scalafmt/issues/2297), closed 2020-12-20); "formatting check issue for code with comments" ([#1550](https://github.com/scalameta/scalafmt/issues/1550), closed 2019-11-11); the docs say outright "The logic also moves comments attached to each import statement" (https://scalameta.org/scalafmt/docs/configuration.html).
- idempotence: output kept growing or alternating, so `--check` never converged — "`newlines.source = keep` (Scalafmt 3.7.1) and fewerBraces cause incorrect and non-idempotent formatting" ([#3448](https://github.com/scalameta/scalafmt/issues/3448), closed 2023-01-30); "New line added before //format: off in v3.8.3 on each run of formatter" ([#4368](https://github.com/scalameta/scalafmt/issues/4368), closed 2024-09-30); "non-idempotent case when `docstrings.oneline = fold`" ([#4536](https://github.com/scalameta/scalafmt/issues/4536), closed 2024-11-11).
- semantic-change: output behaves differently or does not compile — "adds a new line after a `'` expression which changes behaviour of program" ([#3824](https://github.com/scalameta/scalafmt/issues/3824), closed 2024-03-08); "scalafmt output code results in 'illegal start of simple expression'" ([#3589](https://github.com/scalameta/scalafmt/issues/3589), closed 2023-07-19); "`RedundantBraces` rewrite removes parentheses that are required syntactically" ([#3540](https://github.com/scalameta/scalafmt/issues/3540), closed 2023-05-02).
- parse-error-handling: valid source rejected or desynced — "Scalafmt 3.0.0 fails on Scala3 code starting with case statement" ([#2687](https://github.com/scalameta/scalafmt/issues/2687), closed 2021-08-19); "`PositionExceptionImpl` complaining about expected `)` when encountering valid `<-` in for comprehension" ([#3911](https://github.com/scalameta/scalafmt/issues/3911), closed 2024-04-07).
- whitespace-eol-encoding: platform-dependent verdicts and whitespace intolerance — "scalafmt says there is things to format in Windows but not in macos/ununtu" ([#3462](https://github.com/scalameta/scalafmt/issues/3462), closed 2023-02-12); "Scalafmt accepts only space as whitespace in comments, trailing, and pipe" ([#1418](https://github.com/scalameta/scalafmt/issues/1418), closed 2019-05-09).
- line-width-layout: `maxColumn` exceeded or wrapping that ignores it — "maxColumn not respected if certain parts of the code are too long" ([#3637](https://github.com/scalameta/scalafmt/issues/3637), closed 2023-09-19); "No break when line exceeds maxColumn with comma" ([#2936](https://github.com/scalameta/scalafmt/issues/2936), closed 2021-11-30).
- ordering: defaults reorder tokens users relied on — "Align case arrows by default" ([#890](https://github.com/scalameta/scalafmt/issues/890), closed 2017-04-20); "Scalafmt Import rule sorts given alphabetically." ([#3189](https://github.com/scalameta/scalafmt/issues/3189), closed 2022-04-21).
- include-import-analog: sorting imports can reorder program execution — "Sort imports with groups can reorder program execution" ([#2718](https://github.com/scalameta/scalafmt/issues/2718), closed 2021-09-01); "Importing toplevel packages conflicts with [Imports] sorting" ([#3240](https://github.com/scalameta/scalafmt/issues/3240), closed 2022-05-30).
- config-ignore: settings ignored in a scope or rule — "Rewrite rules don't respect `// format: off`" ([#932](https://github.com/scalameta/scalafmt/issues/932), closed 2017-05-17); "scalafmt does not respect fileOverride with `rewrite.scala3` rules" ([#3485](https://github.com/scalameta/scalafmt/issues/3485), closed 2023-03-01); "local comment configuration does not work" ([#1861](https://github.com/scalameta/scalafmt/issues/1861), closed 2020-04-13).
- performance: slow or hanging on big inputs; docs admit "6x slower than Scalariform" (https://scalameta.org/scalafmt/docs/known-issues.html) — "scalafmt 2.5.1 is pretty slow." ([#1949](https://github.com/scalameta/scalafmt/issues/1949), closed 2020-05-04); "Native scalafmt hangs on macOS in git repo with many files" ([#5165](https://github.com/scalameta/scalafmt/issues/5165), closed 2026-01-14).
- crash: exceptions instead of a refusal — "`java.lang.StringIndexOutOfBoundsException` in various files" ([#2037](https://github.com/scalameta/scalafmt/issues/2037), closed 2020-06-19); "cats-effect: Unable to format file due to bug in scalafmt" ([#1714](https://github.com/scalameta/scalafmt/issues/1714), closed 2020-02-17).
- check-exit-codes: a false positive, and one bad file suppressing the whole batch — "scalafmtCheck not accepting formatted code" ([#1231](https://github.com/scalameta/scalafmt/issues/1231), closed 2018-06-29); "`--check`: a single unparseable file suppresses formatting results for every other file in the batch" ([#5359](https://github.com/scalameta/scalafmt/issues/5359), closed 2026-07-25); "`scalafmt --check` reports '--test failed' but no indication as to why" ([#3675](https://github.com/scalameta/scalafmt/issues/3675), closed 2023-11-01).
- partial-range: only git-scoped selection exists, and line-range ratcheting was never implemented — "[FEATURE REQUEST] Apply scalafmt on diffs only" ([#1120](https://github.com/scalameta/scalafmt/issues/1120), closed 2018-03-12); "Feature: Implement git ratcheting" ([#3344](https://github.com/scalameta/scalafmt/issues/3344), closed 2022-10-11).
- embedded-language: non-Scala dialects and shebangs mis-formatted — "Scalafmt 3.0.0 applies new Scala 3 syntax for build.sbt and meta-project files" ([#2688](https://github.com/scalameta/scalafmt/issues/2688), closed 2021-08-19); "Option to skip shebang lines for Scala shell scripts" ([#1297](https://github.com/scalameta/scalafmt/issues/1297), closed 2018-10-16).

**Relevance to hocon-fmt** — high: comment-loss, comment-movement, idempotence, semantic-change, parse-error-handling, include-import-analog, crash, check-exit-codes. As the tool our users run beside us, its failures are the ones our audience already knows: `// format: off` that rewrites still ignore (#932), imports whose sorting moves comments, and `--check` suppressing a batch (#5359). Medium: whitespace-eol-encoding (byte fidelity), config-ignore (our `.hocon-fmt.conf` lookup), partial-range (pre-commit passes changed files; #1120/#3344 mirror it without line ranges), embedded-language (`include`, substitutions, `"""`). Low: ordering (HOCON key order is user data), line-width-layout, performance.

**Probe** — `a = 1 # keep me` where the path gets flattened: still attached, or the file is refused. `include "base.conf" # reason` with a standalone note above `foo = 1`: byte-identical order after formatting. A file mixing `//`, `"""` and deep nesting, formatted twice: identical, `--check` exit 0. `a = ${undefined` and `a =`: no write, clear message, no crash. `include required(file("x.conf"))` among objects: kept in place, never reordered. A batch of one formatted and one unparseable file under `--check`: exit 1, both results reported, the unparseable one refused.

**Development timeline** — 2016-03-03 v0.1.0-RC2 first release; 2016-12-23 v0.5.0 fixes "Search state exploded" except 13 of 27,000 files, the origin of the bail-out model (https://scalameta.org/scalafmt/docs/known-issues.html); 2019-06-30 v2.0.0 is the config/preset overhaul ([#316](https://github.com/scalameta/scalafmt/issues/316), closed 2016-06-07); 2020-06-16 v2.6.0 is a comment-handling wave, including looking for `format: off` in any comment (https://scalameta.org/scalafmt/docs/changelog.html); 2021-08-19 v3.0.0 adds Scala 3 ([#2216](https://github.com/scalameta/scalafmt/issues/2216), closed 2020-10-05) and mis-formats sbt files ([#2688](https://github.com/scalameta/scalafmt/issues/2688)); 2021-11-09 v3.1.0 makes `version`/`runner.dialect` mandatory, which backfired on no-config users ([#3543](https://github.com/scalameta/scalafmt/issues/3543), closed 2023-05-21); 2025-01-13 v3.8.4 makes the off/on tags configurable after the newline-before-off idempotence bug ([#4368](https://github.com/scalameta/scalafmt/issues/4368)); 2026-07-27 v3.11.5 current. **Ideas to migrate** — ignore pragmas with configurable tags for HOCON comments (S, high); a mandatory style-version pin so hook output is reproducible (S, high); git-scoped modes (`--mode changed`/`diff-ref`) for the pre-commit path (M, high); explicit encoding/line-ending preserve settings (S, medium); the `--check` lesson: one bad file must not suppress other results, and exit codes stay 0/1 (S, high; #5359).

## google-java-format

**Tool** — Java's canonical formatter (javac-based, also the AOSP variant), https://github.com/google/google-java-format; 0.1-alpha on 2015-11-09 (https://github.com/google/google-java-format/releases). Stance: "There is no configurability as to the formatter's algorithm for formatting. This is a deliberate design decision" (https://github.com/google/google-java-format/blob/master/README.md).

**Design choices that matter to us**
- Opinionated: only `--aosp` (4-space) versus 2-space Google style; no algorithm config (https://github.com/google/google-java-format/blob/master/README.md).
- Comments are kept but reindented and reflowed; javadoc reflow is on by default (`--skip-javadoc-formatting` stops it), and magic off-comments are refused outright ("Why can't I use magic comments to disable formatting…") (https://github.com/google/google-java-format/blob/master/README.md; https://github.com/google/google-java-format/wiki/FAQ.md).
- Blank lines are canonicalised; keeping the author's blank lines was declined (https://github.com/google/google-java-format/issues/476).
- Imports are sorted and unused ones removed by default, wildcards expanded; escape hatches `--fix-imports-only`, `--skip-sorting-imports`, `--skip-removing-unused-imports` (https://github.com/google/google-java-format/blob/master/README.md).
- 100-column limit; `--aosp` changes indentation only (https://github.com/google/google-java-format/blob/master/README.md).
- Parse errors refuse the whole file (`FormatterException`); the runtime JDK must be at least the source's language level (https://github.com/google/google-java-format/blob/master/README.md).
- `--lines`/`--offset` ranges expand to complete syntactic units, so lines outside the selection may be reformatted (https://github.com/google/google-java-format/issues/942, closed 2023-06-07).
- Check: `--dry-run`/`--set-exit-if-changed`; since 1.7 an unreadable file is reported and gives a non-zero exit (https://github.com/google/google-java-format/releases/tag/google-java-format-1.7). stdin→stdout by default.

**Bug classes**
- comment-movement: comment formatting differs by JDK and position — "Comments are indented before case statements in enhanced switch" ([#876](https://github.com/google/google-java-format/issues/876), closed 2023-01-03); "Different formatting of block line comments with openjdk 23+37-2369" ([#1153](https://github.com/google/google-java-format/issues/1153), closed 2024-08-29); "Formatting of comments is not hermetic" ([#1221](https://github.com/google/google-java-format/issues/1221), closed 2025-03-06).
- idempotence: long comment lines and trailing tabs need two passes — "Non idempotence when applying the formatter over long comment lines" ([#1003](https://github.com/google/google-java-format/issues/1003), closed 2023-12-11); "Handling of trailing tabs in comments not idempotent" ([#422](https://github.com/google/google-java-format/issues/422), closed 2019-12-12).
- include-import-analog: unused-import removal is not idempotent and disagrees with check mode — "Removal of unused static import is not idempotent" ([#1005](https://github.com/google/google-java-format/issues/1005), closed 2023-12-11); "Wildcard import should return failure for dry run" ([#392](https://github.com/google/google-java-format/issues/392), closed 2019-08-07).
- parse-error-handling: newer Java syntax is refused or mangled before support lands — "Code with sealed interfaces can not be formatted" ([#697](https://github.com/google/google-java-format/issues/697), closed 2021-12-14); "Support Java > 11 language features" ([#436](https://github.com/google/google-java-format/issues/436), closed 2020-01-26).
- crash: compiler-legal code triggers assertions and internal errors — "AssertionError for type annotations on arrays" ([#55](https://github.com/google/google-java-format/issues/55), closed 2016-07-08); "Format failed with instructions to raise a bug…" ([#1173](https://github.com/google/google-java-format/issues/1173), closed 2024-10-07).
- crash: JDK internals coupling via add-exports — "java.lang.IllegalAccessError: class com.google.googlejavaformat.java.JavaInput" ([#787](https://github.com/google/google-java-format/issues/787), closed 2022-05-18, 56 comments); "JDK 25 Support Issues with com.sun.tools.javac.util.Log$DeferredDiagnosticHandler" ([#1283](https://github.com/google/google-java-format/issues/1283), closed 2025-09-19).
- embedded-language: text blocks are re-indented, risking literal content — "Issue with text blocks formatting on java 21. Defaulting to extreme left indentation" ([#1113](https://github.com/google/google-java-format/issues/1113), closed 2024-06-18); "Text block formatting bug in 1.25.0" ([#1195](https://github.com/google/google-java-format/issues/1195), closed 2024-11-21); "Automatic deindentation of long text blocks" ([#1087](https://github.com/google/google-java-format/issues/1087), closed 2024-03-20).
- line-width-layout: breaking rules produce absurd reflow — "Long line with string concatenation gets suspiciously short when formatted" ([#504](https://github.com/google/google-java-format/issues/504), closed 2020-07-12); "Java nested lambdas formatting is incredibly poor" ([#990](https://github.com/google/google-java-format/issues/990), closed 2023-11-15).
- ordering: import policy fights IDEs — "wildcard imports are not expanded" ([#113](https://github.com/google/google-java-format/issues/113), closed 2017-01-14); "Expand wildcard imports" ([#1334](https://github.com/google/google-java-format/issues/1334), closed 2026-02-13).
- partial-range: `--lines` expanded beyond what the user asked — "--lines start:end is ignored, whole file is formatted" ([#942](https://github.com/google/google-java-format/issues/942), closed 2023-06-07); the long-standing request for a validation mode — "Validation mode to check if file is correctly formatted" ([#105](https://github.com/google/google-java-format/issues/105), closed 2016-12-12).
- check-exit-codes: the check-mode surface took releases to settle and still misleads — "Wildcard import should return failure for dry run" ([#392](https://github.com/google/google-java-format/issues/392), closed 2019-08-07); "Misleading message for --dry-run with --replace" ([#1094](https://github.com/google/google-java-format/issues/1094), open 2024-04-07); the unreadable-file handling arrived in 1.7 (https://github.com/google/google-java-format/releases/tag/google-java-format-1.7). No comment-loss bug was found in the tracker — their failure mode is moving and rewriting comments, not deleting them — which is unverified as a general claim.

**Relevance to hocon-fmt** — high: comment-movement (their comments are reformatted in place; ours must not move at all), idempotence (long comment lines needing two passes is our second-pass check), include-import-analog (removing an "unused" import is dropping an include), embedded-language (text blocks are our triple-quoted strings, whose bytes are content), parse-error-handling and crash (refuse instead of falling back or asserting), check-exit-codes (pre-commit reads only the code). Medium: line-width-layout, ordering, partial-range.

**Probe** — a 200-char `#` comment on its own line before `k=v`: format twice, byte-identical (`--check` exit 0 both times). `s = """line1\n  line2  """`: inner bytes unchanged. `include required(file("base.conf"))  # keep`: include and comment verbatim. `--check` on a trailing-whitespace-only diff: non-zero, file untouched. `a = ${` and `include "missing.conf"`: refuse, no write, exit code distinct from "would reformat".

**Development timeline** — 2015-11-09 0.1-alpha; 2016-04-13 1.0; 2016-12-12 the validation-mode request ("Validation mode to check if file is correctly formatted", [#105](https://github.com/google/google-java-format/issues/105)) is answered by the `--dry-run`/`--set-exit-if-changed` pair; 2019-01-09 1.7 keeps going on an unreadable file and reports a non-zero exit (release notes); 2021-03-31 1.10 needs `--add-exports` for JDK 16 and #787 (2022-05-18, 56 comments) is the support pain; 2021-05-31 #612 "Java 17 compatibility" (21 comments, closed) continues the JDK treadmill; 2024-11-21 1.25.0 and #1195 "Text block formatting bug in 1.25.0" land the same day; 2025-09-19 #1283 for JDK 25; 2026-10-01 v1.37.0 current. **Ideas to migrate** — ship `--check` and a `--set-exit-if-changed`-style flag as one contract (S, high); keep refusing unreadable input while continuing the rest of the batch with a non-zero summary (S, medium; 1.7); no magic off-comments for style, though we need a region escape hatch for output shape (S, medium); `--skip-*` escape hatches only for pipeline pieces like includes, never for style (M, low).

## ktfmt

**Tool** — Kotlin's formatter built on the google-java-format engine, https://github.com/Kotlin/ktfmt; oldest release v0.11 on 2020-04-13 (https://github.com/Kotlin/ktfmt/releases). Stance: no algorithm configurability beyond three styles — "There is no configurability as to the formatter's algorithm for formatting… This is a deliberate design decision" (https://github.com/Kotlin/ktfmt/blob/main/README.md).

**Design choices that matter to us**
- Styles only: `--meta-style` (default), `--google-style`, `--kotlinlang-style`, plus limited `.editorconfig` via `--enable-editorconfig` (https://github.com/Kotlin/ktfmt/blob/main/README.md).
- No suppression pragma: no `@formatter:off` handling appears in the CLI or formatter source (https://github.com/Kotlin/ktfmt/blob/main/core/src/main/kotlin/org/jetbrains/kotlinx/ktfmt/cli/Main.kt) — every comment of a file is the formatter's to reflow.
- Comments are preserved and reflowed; KDoc width now follows `maxLineWidth` (https://github.com/Kotlin/ktfmt/blob/main/CHANGELOG.md).
- Blank lines before `when` clauses were preserved only in 0.51, after they had been removed by formatting (https://github.com/Kotlin/ktfmt/issues/342, closed 2022-07-23).
- Unused imports are removed; ordering is not sorted, though an editorconfig-driven layout ships (CHANGELOG 0.60; https://github.com/Kotlin/ktfmt/blob/main/CHANGELOG.md).
- Partial ranges since 0.65 (`--lines`, `--offset`), but whole-file cleanup passes (imports, multiline strings) still run (https://github.com/Kotlin/ktfmt/blob/main/README.md).
- Parse errors fail the file; Kotlin compiler upgrades repeatedly break parsing (https://github.com/Kotlin/ktfmt/blob/main/CHANGELOG.md; https://github.com/Kotlin/ktfmt/issues/605, closed 2026-03-12).
- Check: `--dry-run`, `--set-exit-if-changed` (exit 1), `--quiet`; stdin is `-` with `--stdin-name` (https://github.com/Kotlin/ktfmt/blob/main/core/src/main/kotlin/org/jetbrains/kotlinx/ktfmt/cli/ParsedArgs.kt).

**Bug classes**
- comment-loss: comments deleted on format, and around imports — "Comments deleted on format" ([#597](https://github.com/Kotlin/ktfmt/issues/597), closed 2026-02-25); "Crash when comment separate imports" ([#291](https://github.com/Kotlin/ktfmt/issues/291), closed 2022-02-17).
- idempotence: repeated runs drift, three fixes in 18 months — "Formatting isn't idempotent, and repeated invocations produce bad comment formatting" ([#438](https://github.com/Kotlin/ktfmt/issues/438), closed 2024-01-24); "Formatting is not idempotent with `only_add` trailing commas strategy" ([#610](https://github.com/Kotlin/ktfmt/issues/610), closed 2026-04-10); "Ktfmt 0.64 runs are not idempotent" ([#640](https://github.com/Kotlin/ktfmt/issues/640), closed 2026-07-08).
- comment-movement: KDoc reflow moves tags and destroys lists and blank lines — "@sample tags should not be moved within kdoc" ([#406](https://github.com/Kotlin/ktfmt/issues/406), closed 2023-06-21); "Markdown lists not preserved in KDoc comments" ([#7](https://github.com/Kotlin/ktfmt/issues/7), closed 2019-12-27); "ktfmt removes blank lines between when clauses" ([#342](https://github.com/Kotlin/ktfmt/issues/342), closed 2022-07-23).
- include-import-analog: "unused" import removal deletes needed imports — "ktfmt unused imports removal incorrectly removes import with backticks" ([#532](https://github.com/Kotlin/ktfmt/issues/532), closed 2025-04-18); "Crash when comment separate imports" ([#291](https://github.com/Kotlin/ktfmt/issues/291), closed 2022-02-17).
- parse-error-handling: compiler coupling breaks parsing of new syntax — "Cannot use ktfmt with Kotlin 1.6.0" ([#259](https://github.com/Kotlin/ktfmt/issues/259), closed 2021-11-17); "Kotlin compiler v2.3.20 breaks ktfmt with UNRESOLVED_REFERENCE for CONTEXT_RECEIVER_LIST" ([#605](https://github.com/Kotlin/ktfmt/issues/605), closed 2026-03-12).
- semantic-change: tokenizer misreads compiler-valid code — "Lambdas following a statement can be treated as lambda arguments, breaking syntax" ([#459](https://github.com/Kotlin/ktfmt/issues/459), closed 2024-04-23); "ktfmt fails to parse angle brackets in certain cases" ([#51](https://github.com/Kotlin/ktfmt/issues/51), closed 2020-07-02).
- crash: crashes on legal code and in the IDE plugin — "KFMT_idea_plugin crashes with Intellij 2024.3" ([#523](https://github.com/Kotlin/ktfmt/issues/523), closed 2024-12-02); "Crash on legal (but non-standard) getter code" ([#241](https://github.com/Kotlin/ktfmt/issues/241), closed 2021-06-10).
- line-width-layout: output lines exceed the width and trailing commas block collapse — "Formatting creating lines longer than 100 characters" ([#407](https://github.com/Kotlin/ktfmt/issues/407), closed 2023-06-21); "Trailing commas disallow short lines from being collapsed" ([#338](https://github.com/Kotlin/ktfmt/issues/338), closed 2022-07-14).
- check-exit-codes: range/dry-run/stdin semantics took years to answer — "Validate/dry-run mode" ([#212](https://github.com/Kotlin/ktfmt/issues/212), closed 2021-04-21); "When formatting from stdin, ktfmt prints nothing to stdout if there are no changes" ([#267](https://github.com/Kotlin/ktfmt/issues/267), closed 2021-12-28).
- config-ignore: editorconfig arrived late and some passes ignore it — "Canonical .editorconfig" ([#158](https://github.com/Kotlin/ktfmt/issues/158), closed 2020-12-29); "Import layout ignored" ([#592](https://github.com/Kotlin/ktfmt/issues/592), closed 2026-01-29); CHANGELOG 0.60/0.61 also records "Editorconfig not found for relative paths" (https://github.com/Kotlin/ktfmt/blob/main/CHANGELOG.md).
- whitespace-eol-encoding: stdin encoding is assumed, so non-UTF-8 input is mishandled — "Unicode characters through stdin not handled properly with non-standard UTF setting" ([#250](https://github.com/Kotlin/ktfmt/issues/250), closed 2021-08-09) and its duplicate ([#390](https://github.com/Kotlin/ktfmt/issues/390), closed 2023-03-03); "Can we always assume UTF8?" ([#373](https://github.com/Kotlin/ktfmt/issues/373), closed 2022-12-09).

**Relevance to hocon-fmt** — high: comment-loss (their twice-fixed bug is what our LostComment refusal forbids), idempotence (three fixes in 18 months), include-import-analog (removing an "unused" import is dropping an include), parse-error-handling (compiler coupling is our sconfig coupling), crash (a total refuse path). Medium: comment-movement (KDoc reflow shows why we must not reflow comments), line-width-layout, check-exit-codes, config-ignore. Low: semantic-change, whitespace-eol-encoding.

**Probe** — `include "a.conf"\n// c\nb=1`: the comment survives between include and key, byte-identical on the second run. `include file("base.conf")` in a file whose keys are "unused": the include is retained; no cleanup pass. `a = [1, ` and `a = ${x`: refusal with non-zero exit, no write. Unformatted stdin on the second `--stdin` run: still writes the text and exits 0 (not #267's empty output).

**Development timeline** — 2020-04-13 v0.11 oldest release; 2022-07-23 blank lines in `when` bodies had to be restored by a fix ([#342](https://github.com/Kotlin/ktfmt/issues/342)); 2024-06-14 0.51 creates CHANGELOG.md and deletes `--dropbox-style`, a breaking change for style users; 2024-08-20 0.52 reopens the trailing-comma debate ([#512](https://github.com/Kotlin/ktfmt/issues/512), closed 2024-08-21); 2025-12-17 0.60 adds editorconfig and BOM handling; 2026-03-17 0.62 fixes comment deletion, KDoc blank lines and comment width ([#597](https://github.com/Kotlin/ktfmt/issues/597)) — the "comments disappeared" pain; 2026-05-26 0.63 preserves user lambda breaks (PR 614); 2026-06-24 0.64 and 2026-10-07 0.65 add performance and partial formatting, answering #218 from 2021, plus more idempotence fixes ([#640](https://github.com/Kotlin/ktfmt/issues/640)). **Ideas to migrate** — document that whole-file passes (duplicate report, include masking) also run in range mode if we ever add one (S, high); `--dry-run`/`--set-exit-if-changed` with exit 1 (S, high); preserve author line breaks in comments rather than reflow (S, high); a "comments are content" changelog discipline (S, medium).

## ktlint

**Tool** — Kotlin linter and formatter, https://github.com/ktlint/ktlint; 0.1.0 on 2016-07-27 (https://github.com/ktlint/ktlint/releases). Stance: anti-bikeshedding rules but per-rule configurable via `.editorconfig`, with three code styles; since 2.x it is "no longer affiliated with Pinterest open source projects" (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md).

**Design choices that matter to us**
- Configurable: `ktlint_code_style = ktlint_official|intellij_idea|android_studio` plus per-ruleset/per-rule enable/disable (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/rules/configuration-ktlint.md).
- Comments are rule-managed (comment-spacing, discouraged-comment-location); suppression only through `@Suppress("ktlint:rule-set-id:rule-id")` since 0.50 (https://github.com/ktlint/ktlint/blob/master/CHANGELOG.md).
- `no-unused-imports` is disabled by default since 1.7.0 because "it keeps causing problems" (https://github.com/ktlint/ktlint/blob/master/CHANGELOG.md).
- Line width comes from `.editorconfig` `max_line_length`, ignored unless the rule is enabled (CHANGELOG, PR 2783; https://github.com/ktlint/ktlint/blob/master/CHANGELOG.md).
- Parse errors: input must be parseable; the exit-code surface is rich — stdin 3/4, IO 2, invalid option path 5, unsupported ruleset 6, reporter 7, `--force-lint-after-format` 123 (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md).
- Default run validates, `--format`/`-F` autocorrects, and the docs warn that autocorrect may need a second run and "might result in an endless loop" (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md).
- stdin: `--stdin` and `--stdin-path`; formatted code on stdout, violations on stderr (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md).
- `.editorconfig` discovery: all files along the path merged, project root by default, `--editorconfig=` as fallback (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md).

**Bug classes**
- semantic-change: formatting changed program meaning — "Formatting changes semantics of the code when using functions with the expression body written in the next line" ([#1064](https://github.com/ktlint/ktlint/issues/1064), closed 2021-01-20); "Double parentheses are wrongly formatted" ([#2418](https://github.com/ktlint/ktlint/issues/2418), closed 2023-12-09).
- comment-movement: blank lines injected around comments and imports — "Comments above annotations are separated by the annotation with a blank line" ([#2416](https://github.com/ktlint/ktlint/issues/2416), closed 2023-12-05); "Ignore comments in imports when formatting" ([#2670](https://github.com/ktlint/ktlint/issues/2670), closed 2024-05-27).
- comment-loss: comment content broken by indentation and EOL handling — "Tab indentation breaks KDoc comments" ([#850](https://github.com/ktlint/ktlint/issues/850), closed 2020-08-24); "Trailing spaces not removed in multiline comment block" ([#1197](https://github.com/ktlint/ktlint/issues/1197), closed 2021-08-05).
- include-import-analog: import ordering and removal churn, ending in the default being turned off — "Wildcard imports" ([#48](https://github.com/ktlint/ktlint/issues/48), closed 2017-05-30, 64 comments); "Do not run `no-unused-imports` rule by default" ([#3038](https://github.com/ktlint/ktlint/issues/3038), closed 2025-07-05).
- config-ignore: disabled rules ignored, or config parsing breaking the run — "ktlint 1.1.0 doesn't respect disabled discouraged-comment-location rule in .editorconfig" ([#2445](https://github.com/ktlint/ktlint/issues/2445), closed 2023-12-19); ".editorconfig with empty values like from IntelliJ export breaks parsing" ([#2824](https://github.com/ktlint/ktlint/issues/2824), closed 2024-10-04).
- config-ignore: suppression directives changed under users and misfire — "Block ktlint-disable directive not working" ([#967](https://github.com/ktlint/ktlint/issues/967), closed 2020-11-17); "[FR] "@file:Suppress" on wrong location triggers unclear "Annotations should occur immediately before the annotated construct"" ([#3334](https://github.com/ktlint/ktlint/issues/3334), closed 2026-07-02); 0.50 replaced `ktlint-disable`/`ktlint-enable` with `@Suppress` (https://github.com/ktlint/ktlint/blob/master/CHANGELOG.md).
- crash: internal errors during `--format` — "Nullpointer exception for if-else statement having an empty THEN block" ([#2135](https://github.com/ktlint/ktlint/issues/2135), closed 2023-07-16); "Starting a line with || causes internal error from ktlint --format" ([#1993](https://github.com/ktlint/ktlint/issues/1993), closed 2023-05-05).
- parse-error-handling: compiler upgrades break the parser — "Kotlin 1.5.0 breaks ktlint" ([#1142](https://github.com/ktlint/ktlint/issues/1142), closed 2021-05-06); "Context (parameter) keyword causes unexpected formatting of the function parameters" ([#3120](https://github.com/ktlint/ktlint/issues/3120), closed 2025-09-08).
- whitespace-eol-encoding: CRLF converted to LF on Windows — "Ktlint 1.3.* converts crlf to lf on Windows" ([#2747](https://github.com/ktlint/ktlint/issues/2747), closed 2024-07-20); "File should not start with whitespace" ([#1563](https://github.com/ktlint/ktlint/issues/1563), closed 2022-07-31).
- line-width-layout: the width rule cannot be escaped and fights strings — "The maximum line length of 120 has been exceeded. The rule cannot be modified or disabled." ([#1496](https://github.com/ktlint/ktlint/issues/1496), closed 2022-06-15); "Ignore line length in string literals" ([#659](https://github.com/ktlint/ktlint/issues/659), closed 2019-11-26); "Conflict between `binary-expression-wrapping` and `ktlint_standard_range-spacing`" ([#2766](https://github.com/ktlint/ktlint/issues/2766), closed 2024-08-11).
- idempotence: admitted by design — the docs say some violations remain for the next run and reruns "might result in an endless loop" (https://github.com/ktlint/ktlint/blob/master/documentation/release-latest/docs/install/cli.md); "Function Signature flip-flops between violations with long expression body" ([#1897](https://github.com/ktlint/ktlint/issues/1897), closed 2023-03-29); "Formatting enum class with member definition and missing trailing commas causes rule violations on first run" ([#1786](https://github.com/ktlint/ktlint/issues/1786), closed 2023-01-23).
- other: the opinionation backlash — "ktlint has become too opinionated" ([#2703](https://github.com/ktlint/ktlint/issues/2703), closed 2024-06-17); "Annotation wrapping before explicit constructor (ktlint_official)" ([#2138](https://github.com/ktlint/ktlint/issues/2138), closed 2023-07-20, 53 comments).

**Relevance to hocon-fmt** — high: semantic-change (our masked-output parse check exists for this), comment-movement and comment-loss (blank lines around comments, KDoc breakage), include-import-analog (#3038's "keeps causing problems" is the strongest precedent for never removing an include), config-ignore (`@Suppress` churn and `.editorconfig` silently ignored are the failure our explicit `--config` must not repeat), idempotence (their docs admit non-convergence; ours must refuse instead). Medium: crash and parse-error-handling (their exit-code table is a model), whitespace-eol-encoding (CRLF→LF is corruption for us). Low: line-width-layout, other.

**Probe** — `a = { b = 1 }` versus `a.b = 1`: same resolved config after formatting (our masked-output parse check). `a = 1\n# c\nb = 2`: no blank line inserted, comment stays. `# # #   trailing spaces  `: bytes preserved within the documented normalisations, `--check` sees a diff rather than silently fixing. `include "base.conf"` with no reference to its keys: never removed, never flagged. `--check` from a subdirectory with `.hocon-fmt.conf` above: found, or a documented default, never a silent miss. CRLF file: preserved or refused.

**Development timeline** — 2016-07-27 0.1.0 first release; 2017-05-30 wildcard imports are the early fight ([#48](https://github.com/ktlint/ktlint/issues/48), 64 comments); 2019-07-15 import ordering by default alienates IDE users ([#527](https://github.com/ktlint/ktlint/issues/527), closed 2019-07-15); 2023-06-29 0.50 removes `ktlint-disable`/`ktlint-enable` for `@Suppress` (CHANGELOG); 2023-09-05 1.0.0; 2023-12-19 1.1.0's `.editorconfig` disable being ignored ([#2445](https://github.com/ktlint/ktlint/issues/2445)); 2024-07-20 1.3.x's CRLF→LF regression ([#2747](https://github.com/ktlint/ktlint/issues/2747)) and the opinionation backlash ([#2703](https://github.com/ktlint/ktlint/issues/2703), 2024-06-17); 2025-07-14 1.7.0 turns `no-unused-imports` off by default because "it keeps causing problems" ([#3038](https://github.com/ktlint/ktlint/issues/3038)); 2026-08-20 2.0.0-ALPHA-4 removes deprecated rules and directives (CHANGELOG). **Ideas to migrate** — a published exit-code table, tested per platform (S, high); every behavioural switch in one documented config with `--config` (M, medium); "format twice, compare, refuse on a loop" internally before writing (M, high); an explicit never-do list (no comment reflow, no EOL rewrite, no include removal) in docs/limitations.md (S, medium).

## clang-format

**Tool** — the one formatter for C/C++/Obj-C, in the LLVM monorepo https://github.com/llvm/llvm-project; first documented in Clang 3.3 (https://releases.llvm.org/3.3/docs/ReleaseNotes.html) and maintained since. Stance: no house style at all — "ClangFormat describes a set of tools that are built on top of LibFormat", and every choice is a style option (https://clang.llvm.org/docs/ClangFormat.html) — the opposite pole to gofmt.

**Design choices that matter to us**
- Fully configurable: the style is data, via `.clang-format` and `--style=` (https://clang.llvm.org/docs/ClangFormatStyleOptions.html).
- Comments: `ReflowComments` rewraps them, while `CommentPragmas` marks "comments with special meaning, which should not be split into lines or otherwise changed" (https://clang.llvm.org/docs/ClangFormatStyleOptions.html).
- Blank lines: `MaxEmptyLinesToKeep` (non-idempotent at 0) and `SeparateDefinitionBlocks`, which inserts or removes blank lines as a formatting action (https://github.com/llvm/llvm-project/issues/26345, closed 2015-12-30).
- Ordering: `SortIncludes`/`IncludeBlocks` reorder and regroup `#include` blocks — code-moving, not whitespace (https://clang.llvm.org/docs/ClangFormatStyleOptions.html).
- Line width: `ColumnLimit`, where 0 means no limit (https://clang.llvm.org/docs/ClangFormatStyleOptions.html).
- Parse errors: token-level best effort, never refuses; a C file whose formatting fails falls back to C++ formatting (https://github.com/llvm/llvm-project/issues/132832, closed 2025-03-24).
- Ignore pragmas: `// clang-format off/on`, `DisableFormat`, and `.clang-format-ignore` files since LLVM 18 (https://releases.llvm.org/18.1.0/tools/clang/docs/ReleaseNotes.html).
- Config discovery: `.clang-format` from parent directories, `--fallback-style`, stdin takes `--assume-filename` (https://clang.llvm.org/docs/ClangFormat.html).
- Check: no `--check`; `--dry-run` prints and `-Werror` makes differences errors, `--fail-on-incomplete-format` exits 1 (https://clang.llvm.org/docs/ClangFormat.html).
- Ranges: `--lines a:b` or `--offset/--length`, "Can only be used with one input file" (https://clang.llvm.org/docs/ClangFormat.html).

**Bug classes**
- comment-loss: comments deleted or truncated — "[Formatter] Slash of last `//` comment of indented code deleted" ([#53799](https://github.com/llvm/llvm-project/issues/53799), closed 2022-02-13); "[clang-format] When processing constexpr inline, the middle macro will be deleted" ([#80579](https://github.com/llvm/llvm-project/issues/80579), closed 2024-02-04); "[clang-format] BreakConstructorInitializers doesn't preserve NOLINT comments" ([#41128](https://github.com/llvm/llvm-project/issues/41128), closed 2019-05-07).
- comment-movement: comments re-anchored to other lines — "Comments in macros moved to different lines" ([#15529](https://github.com/llvm/llvm-project/issues/15529), closed 2013-02-05); "[clang-format] Fail to reindent standalone comments when `AlignTrailingComments.Kind: Leave`" ([#196663](https://github.com/llvm/llvm-project/issues/196663), closed 2026-05-08); "[clang-format] `SeparateDefinitionBlocks: Always` separates trailing block comments (relevant for `// NOLINTEND`)" ([#189384](https://github.com/llvm/llvm-project/issues/189384), closed 2026-03-30).
- idempotence: a second run differs or oscillates — "clang-format not idempotent with long comment containing tabs" ([#51808](https://github.com/llvm/llvm-project/issues/51808), closed 2021-11-10); "`clang-format` is not idempotent on certain files" ([#107616](https://github.com/llvm/llvm-project/issues/107616), closed 2024-09-06); "[clang-format] OneLineFormatOffRegex causes comment above matched line to oscillate indentation" ([#200521](https://github.com/llvm/llvm-project/issues/200521), closed 2026-05-29).
- semantic-change: include sorting breaks builds — "[clang-format] Google-Style on sorting Includes moves them into comment & breaks code" ([#97539](https://github.com/llvm/llvm-project/issues/97539), closed 2024-07-03); "Clang-format might cause compilation errors if a local library header is included with angle brackets" ([#58300](https://github.com/llvm/llvm-project/issues/58300), closed 2022-10-11); "[clang-format] RemoveSemicolon deletes the semicolon terminating an Objective-C block literal with a generic return type" ([#219713](https://github.com/llvm/llvm-project/issues/219713), closed 2026-08-29).
- parse-error-handling: language misdetection instead of refusal — "[clang-format] Fix breaking change in 20.1.0 by automatically falling back to Cpp formatting if C formatting fails" ([#132832](https://github.com/llvm/llvm-project/issues/132832), closed 2025-03-24); "[clang-format] bug in c formatting when "switch" appears as a token" ([#114408](https://github.com/llvm/llvm-project/issues/114408), closed 2024-10-31).
- whitespace-eol-encoding: CRLF and BOM rewritten — "clang-format -i replaces LF by CRLF" ([#25373](https://github.com/llvm/llvm-project/issues/25373), closed 2015-09-30); "DOS line endings (\r\n) result in incorrect output with clang-format" ([#34870](https://github.com/llvm/llvm-project/issues/34870), closed 2017-12-04); "Clang adds initial newline for files that start with UTF-8 BOM." ([#18127](https://github.com/llvm/llvm-project/issues/18127), closed 2013-10-31).
- line-width-layout: wrapping wrong even at the limits — "clang-format ColumnLimit=0 produces very long condition lines" ([#23201](https://github.com/llvm/llvm-project/issues/23201), closed 2015-03-06); "[clang-format] Bug - clang-format keeps appending `\` when `ReflowComments: Never` and `ColumnLimit: 0`" ([#164282](https://github.com/llvm/llvm-project/issues/164282), closed 2025-10-20).
- config-ignore: ignore mechanisms quietly ineffective — "[clang-format] does not respect .clang-format-ignore (version 18.1.8)" ([#108337](https://github.com/llvm/llvm-project/issues/108337), closed 2024-09-12); "[clang-format] QualifierOrder ignores `// clang-format off`" ([#53643](https://github.com/llvm/llvm-project/issues/53643), closed 2022-02-07); "clang-format: Disabling Formatting on a one line" ([#54334](https://github.com/llvm/llvm-project/issues/54334), closed 2022-03-11).
- performance: pathologically slow inputs — "clang-format: /**/ before macro removes line breaks and runs 200x slower" ([#40828](https://github.com/llvm/llvm-project/issues/40828), closed 2019-04-12); "[clang-format] LLVM ERROR: out of memory when formatting ext/nlohmann/json.hpp (clang-format-20)" ([#184040](https://github.com/llvm/llvm-project/issues/184040), closed 2026-03-01).
- crash: assertions and crashes in macro reconstruction — "Assertion failed: Shift >= 0, file ...WhitespaceManager.cpp, line 245" ([#32854](https://github.com/llvm/llvm-project/issues/32854), closed 2017-06-19); "[clang-format] crashes upon expanding function macros with missing closing paren" ([#131157](https://github.com/llvm/llvm-project/issues/131157), closed 2025-03-13).
- check-exit-codes: `--dry-run` disagrees with formatting — "`clang-format` and `clang-format --dry-run -Werror` disagree regarding inline namespace" ([#82246](https://github.com/llvm/llvm-project/issues/82246), closed 2024-02-19); "Clang format: Dry-run fails without expected changes" ([#61048](https://github.com/llvm/llvm-project/issues/61048), closed 2023-02-28).
- partial-range: ranges leak outside the selection or are ignored — "clang-format -lines removes a line outside of its range" ([#52993](https://github.com/llvm/llvm-project/issues/52993), closed 2022-01-04); "[clang-format] command line parameter -lines ignored when using QualifierAlignment" ([#54888](https://github.com/llvm/llvm-project/issues/54888), closed 2022-04-13).
- embedded-language: macro bodies and string-like spans parsed as C++ — "preprocessor directives indentation" ([#17736](https://github.com/llvm/llvm-project/issues/17736), closed 2013-09-25); "clang-format c comment in preprocessor macro" ([#21069](https://github.com/llvm/llvm-project/issues/21069), closed 2014-08-18).
- crash: check mode alone crashes on odd bytes — "[clang-format] --dry-run crashes on C file containing embedded NUL byte, but works fine without --dry-run flag" ([#188500](https://github.com/llvm/llvm-project/issues/188500), closed 2026-03-25); "clang-format --dry-run segfault on a binary file" ([#44786](https://github.com/llvm/llvm-project/issues/44786), open 2020-04-06).

**Relevance to hocon-fmt** — high: comment-loss and comment-movement (their pragma comments are our includes: `// NOLINT` moved or deleted is an include moved or deleted), idempotence (pre-commit reruns), semantic-change (#97539 is the include-sort failure, and HOCON's include order decides values), parse-error-handling (they fall back silently where we refuse), whitespace-eol-encoding, config-ignore (off/on and ignore files that do not apply), crash (dry-run diverging from write is exactly the `--check`-vs-write split we cannot have), check-exit-codes. Medium: line-width-layout, performance (huge pathological inputs should be refused early), embedded-language (macro bodies are our multi-line strings and substitutions). Low: partial-range.

**Probe** — `include "base.conf"` between two keys, and `include "x.conf" # why`: no reordering, no comment loss, `--check` clean after formatting. `//` and `#` comments, tabs, CRLF in one file: format twice, byte-identical second pass, CRLF preserved or refused. `s = """line # not comment\n// literal"""`: inner bytes untouched. `a = ${`, stray `}`, unterminated `"""`: refusal, no stack trace, no write, distinct code. BOM + CRLF + no final newline: preserved bytes outside reformatted spans.

**Development timeline** — 2013-06-17 Clang 3.3 documents clang-format (https://releases.llvm.org/3.3/docs/ReleaseNotes.html); Clang 3.7 adds `DisableFormat`/`CommentPragmas`, the region-protection idea (style docs); 2015-12-30 `MaxEmptyLinesToKeep: 0` non-idempotence is filed ([#26345](https://github.com/llvm/llvm-project/issues/26345)); 2019-04-12 the 200x slowdown with `/**/` before a macro ([#40828](https://github.com/llvm/llvm-project/issues/40828)); 2024-03-06 LLVM 18 adds `.clang-format-ignore` and flips `BreakAfterAttributes` (https://releases.llvm.org/18.1.0/tools/clang/docs/ReleaseNotes.html), with regressions filed within weeks ([#86539](https://github.com/llvm/llvm-project/issues/86539), closed 2024-03-25; [#108337](https://github.com/llvm/llvm-project/issues/108337), closed 2024-09-12); 2025-03-04 LLVM 20.1.0's C/C++ breaking change is patched by the Cpp fallback ([#132832](https://github.com/llvm/llvm-project/issues/132832)); 2026-04-28 idempotence regressions continue into 22 ([#194717](https://github.com/llvm/llvm-project/issues/194717), closed 2026-04-28). **Ideas to migrate** — `# hocon-fmt: off/on` covering one-line and trailing-text forms, tested (S, high); `--check` exit codes proven equal to "would write" by tests (S, high; #82246/#61048); ignore-file discovery as a tested contract (M, medium); if ranges ever land, assert nothing outside the selection changes (L, medium; #52993); keep refusing instead of silently falling back, but say why (S, high; #132832).

## swift-format

**Tool** — Swift's formatter and linter, https://github.com/swiftlang/swift-format (formerly apple/swift-format); first release 0.50200.0 on 2020-04-01 (https://github.com/swiftlang/swift-format/releases/tag/0.50200.0). Stance: "No default Swift code style guidelines have yet been proposed. The style that is currently applied by swift-format is just one possibility" (https://github.com/swiftlang/swift-format/blob/main/README.md).

**Design choices that matter to us**
- Configurable through a JSON `.swift-format`; rules can be enabled/disabled and defaults dumped with `dump-configuration` (https://github.com/swiftlang/swift-format/blob/main/Documentation/Configuration.md).
- Ignore pragmas: `// swift-format-ignore[: rules]` and its `-file` variant suppress "the next node … all children", only on declarations and statements (https://github.com/swiftlang/swift-format/blob/main/Documentation/IgnoringSource.md).
- Comments are generally not rewrapped — "Column limits don't seem to apply to comments" (https://github.com/swiftlang/swift-format/issues/469, open 2023-01-09) — though inline spacing is normalised (https://github.com/swiftlang/swift-format/issues/868, closed 2024-10-22).
- Blank lines: `maximumBlankLines` defaults to 1, `indentBlankLines` to false (https://github.com/swiftlang/swift-format/blob/main/Documentation/Configuration.md).
- `OrderedImports` sorts imports; sectioning is configurable and access-level grouping missing (https://github.com/swiftlang/swift-format/issues/1128, closed 2025-12-18; https://github.com/swiftlang/swift-format/issues/703, open 2024-03-15).
- Line width: `lineLength` defaults to 100 (https://github.com/swiftlang/swift-format/blob/main/Documentation/Configuration.md).
- Parse errors: works from the SwiftSyntax tree and crashes on malformed edge inputs rather than refusing — "[SR-11101] swift-format crashes on empty file or file with only comments" (https://github.com/swiftlang/swift-format/issues/1155, closed 2019-07-11).
- No partial-range formatting; the feature request was closed unimplemented (https://github.com/swiftlang/swift-format/issues/297, closed 2022-02-18).
- Check: `lint` prints diagnostics but "lint warnings do not prevent a successful exit" unless `--strict`; `--in-place` overwrites with no backup; stdin is read when no paths are given, with `--assume-filename` (https://github.com/swiftlang/swift-format/blob/main/README.md).

**Bug classes**
- comment-loss: comment-only blocks removed by import sorting, and comments deleted by a lint rule — "Comment-only code blocks are removed when OrderedImports is enabled" ([#1080](https://github.com/swiftlang/swift-format/issues/1080), closed 2025-10-25); "`NoCasesWithOnlyFallthrough` silently deletes a comment trailing the `case` label" ([#1274](https://github.com/swiftlang/swift-format/issues/1274), open 2026-08-25).
- comment-movement: imports jump over headers and comments duplicate — "`OrderedImports` sometimes moves import before file header" ([#772](https://github.com/swiftlang/swift-format/issues/772), closed 2024-07-18); "swift-format Incorrectly duplicates comments to subsequent lines" ([#843](https://github.com/swiftlang/swift-format/issues/843), open 2024-10-10); "Formatting results in duplicated top-level documentation" ([#741](https://github.com/swiftlang/swift-format/issues/741), open 2024-05-11).
- idempotence: no issue matches "idempotent", the nearest being output that changes between versions and duplicated comments — "602.0.0 and 603.0.0 produce different output with the same configuration" ([#1242](https://github.com/swiftlang/swift-format/issues/1242), open 2026-07-09); "swift-format Incorrectly duplicates comments to subsequent lines" ([#843](https://github.com/swiftlang/swift-format/issues/843), open 2024-10-10). This absence of reports is unverified, not proof.
- semantic-change: shebang lines and unsafe expressions are broken — "Shebang syntax is broken by swift-format 6.3" ([#1194](https://github.com/swiftlang/swift-format/issues/1194), closed 2026-04-27); "swift-format still can't treat `unsafe` expressions correctly in some cases" ([#977](https://github.com/swiftlang/swift-format/issues/977), closed 2025-04-05).
- parse-error-handling: crashes instead of a refusal — "[SR-11101] swift-format crashes on empty file or file with only comments" ([#1155](https://github.com/swiftlang/swift-format/issues/1155), closed 2019-07-11); "Incorrect formatting when disabling #if indentation in a postfix expression" ([#944](https://github.com/swiftlang/swift-format/issues/944), open 2025-02-21); "swift-format-ignore in conditionally-compiled code results in an assertion failure in PrettyPrint.swift" ([#1079](https://github.com/swiftlang/swift-format/issues/1079), closed 2025-10-22).
- whitespace-eol-encoding: trailing-whitespace and Windows empty-line changes — "add configuration option to trim trailing whitespaces" ([#1097](https://github.com/swiftlang/swift-format/issues/1097), closed 2025-11-19); "Extra empty line between import on Windows" ([#1250](https://github.com/swiftlang/swift-format/issues/1250), closed 2026-07-17); "TrailingWhitespace is giving a false positive" ([#997](https://github.com/swiftlang/swift-format/issues/997), closed 2025-04-17).
- line-width-layout: assignments and operators break although the line fits — "Assignment RHS is moved to new line even when assignment fits max line length" ([#1300](https://github.com/swiftlang/swift-format/issues/1300), open 2026-09-18); "Line break incorrectly inserted before infix operator when trying to limit line length" ([#1141](https://github.com/swiftlang/swift-format/issues/1141), open 2026-01-04); "`lineLength` with `multilineTrailingCommaBehavior : alwaysUsed` seems broken" ([#1219](https://github.com/swiftlang/swift-format/issues/1219), open 2026-06-21).
- ordering: import sorting has open correctness bugs — "[SR-15565] Swift Format OrderedImports incorrectly sorts uppercased imports" ([#301](https://github.com/swiftlang/swift-format/issues/301), open 2021-12-06); "OrderedImports should create separate groups for different access levels" ([#703](https://github.com/swiftlang/swift-format/issues/703), open 2024-03-15).
- config-ignore: ignores that don't apply, or config that changes defaults silently — "Ignoring a rule on a variable declaration doesn't work" ([#771](https://github.com/swiftlang/swift-format/issues/771), open 2024-07-18); "False reports and/or `// swift-format-ignore: DontRepeatTypeInStaticProperties` doesn't work." ([#816](https://github.com/swiftlang/swift-format/issues/816), closed 2024-09-24); "specifying `rules` in `.swift-format` file seems to change the default value for some rules" ([#1168](https://github.com/swiftlang/swift-format/issues/1168), open 2026-03-15).
- performance: formatting is slow, parallel mode slower and once segfaulting — "formatting + linting is too slow" ([#468](https://github.com/swiftlang/swift-format/issues/468), open 2023-01-06); "swift-format lint is slower when run with the parallel option" ([#1069](https://github.com/swiftlang/swift-format/issues/1069), open 2025-10-02); "[SR-14852] Parallel mode segfaults" ([#308](https://github.com/swiftlang/swift-format/issues/308), closed 2021-06-29).
- crash: crashes tied to the ignore pragma — "Crash when swift-format-ignore precedes a statement inside a switch case" ([#1301](https://github.com/swiftlang/swift-format/issues/1301), open 2026-09-18); "[SR-14529] swift-format-ignore inside switch causes linter to crash" ([#309](https://github.com/swiftlang/swift-format/issues/309), open 2021-04-26).
- check-exit-codes: lint exited 0 after finding violations, and reports were inconsistent — "[SR-12785] swift-format -m lint has zero exit code after identifying style violations" ([#327](https://github.com/swiftlang/swift-format/issues/327), closed 2020-05-11); "Lint is inconsistent on how source paths are reported" ([#818](https://github.com/swiftlang/swift-format/issues/818), closed 2024-09-24).
- embedded-language: multi-line strings and interpolation are re-indented wrongly — "Interpolation wrapping breaks multi-line string indentation" ([#1226](https://github.com/swiftlang/swift-format/issues/1226), open 2026-06-25); "Re-indenting multiline string literal with multiline tertiary expression fails" ([#783](https://github.com/swiftlang/swift-format/issues/783), open 2024-07-26).

**Relevance to hocon-fmt** — high: comment-loss and comment-movement (deleting a comment-only block is our LostComment refusal; duplicating a header is our moved-include check), semantic-change (a broken shebang is the "non-config line in the file" case), parse-error-handling and crash (crash-on-empty proves a refusal path must be built, which our `Verdict` is), whitespace-eol-encoding (Windows empty-line churn), config-ignore (an ignore that silently doesn't apply is worse than none), check-exit-codes (a lint that exits 0 is the one thing `--check` cannot ship with; `--strict` is their retrofit). Medium: line-width-layout, ordering, performance, embedded-language (interpolation and `"""` are our opaque spans). Low: idempotence (no reports — a warning that idempotence needs property tests, not issue mining).

**Probe** — a licence banner above `include "base.conf"` and a `# section` below: order and attachment unchanged (lessons #772/#1080). Empty file, file with comments only, unterminated `include`: clean refusal code, no stack trace (lessons #1155/#1301). `--check` on formatted / unformatted / refused input: 0, non-zero, distinct non-zero; second format byte-identical (lessons #327/#1242). `# hocon-fmt: off` before a key and inside a nested object: honoured or loudly rejected, never a silent half-apply (lessons #771/#816). BOM+CRLF file with `s = """# not a comment"""` and `${?ENV}`: byte-preservation outside reformatted spans (lessons #1226/#1097).

**Development timeline** — 2020-04-01 0.50200.0 first release (releases API); 2020-05-11 lint exited 0 despite violations ([#327](https://github.com/swiftlang/swift-format/issues/327)), later answered by `--strict`; 2021-06-29 parallel mode segfaults ([#308](https://github.com/swiftlang/swift-format/issues/308)); 2022-02-18 range formatting is refused as unsupported ([#297](https://github.com/swiftlang/swift-format/issues/297)); 2024-10-11 an infinite loop on Linux when `.swift-format` is missing ([#847](https://github.com/swiftlang/swift-format/issues/847), closed 2024-10-11) — config discovery as user pain; 2025-10-25 comment-only blocks deleted by import sorting ([#1080](https://github.com/swiftlang/swift-format/issues/1080)); 2026-07-09 602.0.0 and 603.0.0 produce different output under the same configuration ([#1242](https://github.com/swiftlang/swift-format/issues/1242)); 2026-09-18 604.0.0 ships with the ignore-crash still open ([#1301](https://github.com/swiftlang/swift-format/issues/1301)). **Ideas to migrate** — pragma semantics "ignore the next node/subtree, optionally per rule", with tests per form (M, high; #771/#1274); a strict check mode whose exit codes are contract-tested (S, high; #327); refusal tests for empty, comment-only and malformed input (S, high; #1155/#1301); config-key completeness validation so a partial `rules` cannot change defaults silently (S, medium; #1168).

## Across the family

- The same few bug classes recur in every tracker, in this order of pain: comments lost or moved, a second pass that differs, output that no longer means the same, and check mode that disagrees with write mode. hocon-fmt's refusal design targets exactly these; the profiles are the evidence for keeping it.
- Configurability is a maintenance tax everywhere it is offered (scalafmt's fileOverride bugs, rustfmt's unstable options, ktlint's `.editorconfig` regressions), and the most successful tools are the least configurable (gofmt). hocon-fmt's four options are already near gofmt's end of the spectrum.
- `--check` earns trust only if its exit code is proven equal to "a write would happen" on every path (black #5474, clang-format #82246/#61048, swift-format #327, gofmt #46289) — our exit-code contract deserves the same property tests.
- Pragma and ignore mechanisms are a recurring source of silent corruption (rustfmt's half-working `#[rustfmt::skip]`, swift-format's ignore crashes, ktlint's removed directives). Any `# hocon-fmt: off` we add must be implemented fully or not at all.
- The most portable idea in this family: a written stability/limitations ledger plus property tests over generated input (black's AST-equivalence check, ruff's fixture contract, gofmt's comment-placement corpus). hocon-fmt already has docs/limitations.md and FormatterPropertiesSpec; this research argues for growing both.
