# Config-like languages closest to HOCON

Research snapshot: 2026-10-09. Read against this repository's limitations, architecture and ideas, plus the canonical HOCON migration ledger. No code changes or ledger updates. Paired issue/PR links are primary evidence, not independent reproductions; “closed” does not imply fixed in a release. Dates in evidence tables are creation dates; timeline dates say when a change merged or a release was published.

Method: GitHub issue searches sorted by comment count, explicit comment/idempotence searches, individual REST issue/PR reads, release APIs, official docs and formatter source. REST search hit a shared rate limit; GraphQL search and direct APIs supplied the remaining evidence. Searches included historical and current reports, not only the `bug` label. Small trackers are reported as such instead of inventing ten defects. Related frontends/libraries are grouped where they share a representation or workflow; their differences are called out. First releases that were not established are marked **unverified**, rather than inferred from repository creation or the oldest page of release results.

The strongest transfer is source fidelity: a stable, parseable rendering can still lose a value, alter a string, move an include across an override, or detach a tooling directive. The probes therefore check values and source relationships as well as the fixed point. Comment spelling already intentionally normalized by hocon-fmt is not treated as a new defect.

## HCL: terraform fmt / hclfmt / hclwrite

**Tool** — HCL; [Terraform](https://github.com/hashicorp/terraform) and [HCL](https://github.com/hashicorp/hcl). First formatter releases **unverified**; the HCL release API records v2.0.0 published 2020-01-03. HashiCorp specifies a canonical, mostly nonconfigurable style whose details may change between versions.
**Design choices that matter to us**

- Terraform formats files/directories or `-` for stdin; recursion is opt-in. [CLI](https://developer.hashicorp.com/terraform/cli/commands/fmt).
- `-check` implies no writes and returns nonzero for changes; `-diff` alone can accompany writes. [CLI](https://developer.hashicorp.com/terraform/cli/commands/fmt).
- `hclwrite.Format` edits tokens without building an AST and explicitly ignores syntax errors; never confuse this with safe whole-file formatting. [API](https://raw.githubusercontent.com/hashicorp/hcl/main/hclwrite/public.go).
- `hclwrite.ParseConfig` instead supplies a syntax-preserving edit tree and diagnostics. [API](https://raw.githubusercontent.com/hashicorp/hcl/main/hclwrite/public.go).
- `hclfmt -check` means syntax checking; `-require-no-change` detects changed bytes, and `-w` may still write them. [Source](https://raw.githubusercontent.com/hashicorp/hcl/main/cmd/hclfmt/main.go).
- Terraform parses before formatting and refuses syntax errors; its application layer adds label/interpolation rewrites. [Source](https://raw.githubusercontent.com/hashicorp/terraform/main/internal/command/fmt.go).
- Attribute alignment is opinionated; comment-only lines divide alignment groups. [hashicorp/terraform#37656 “terraform fmt - comments in the middle of blocks”](https://github.com/hashicorp/terraform/issues/37656) (closed, 2025-09-23).
- Long-line wrapping and ignore regions are requests, not documented capabilities. [hashicorp/terraform#22703 “`terraform fmt` doesn't break long lines”](https://github.com/hashicorp/terraform/issues/22703) (open, 2019-09-05); [hashicorp/terraform#36208 “terraform fmt should have the ability to ignore certain parts of the code”](https://github.com/hashicorp/terraform/issues/36208) (open, 2024-12-12).

## TOML: Taplo / Even Better TOML

**Tool** — TOML; [Taplo](https://github.com/tamasfe/taplo). First release **unverified** (release pagination does not establish it). Maintainers expose detailed layout controls through a formatter shared by CLI/library/editor integrations.
**Design choices that matter to us**

- Formatting normally refuses syntax errors; `--force` explicitly permits best effort. [CLI](https://taplo.tamasfe.dev/cli/usage/formatting.html).
- `taplo fmt -` uses stdin/stdout; `--check` checks without rewriting. [CLI](https://taplo.tamasfe.dev/cli/usage/formatting.html).
- Width, indentation, array expansion/collapse, alignment and blank-line limits are configurable. [Options](https://taplo.tamasfe.dev/configuration/formatter-options.html).
- Key/array reordering is optional; array sorting can change application meaning. [Options](https://taplo.tamasfe.dev/configuration/formatter-options.html).
- `.taplo.toml`/`taplo.toml`, include/exclude globs and rules govern effective options. [Config](https://taplo.tamasfe.dev/configuration/file.html).
- `--stdin-filepath` must apply the same path-sensitive rules as file input. [tamasfe/taplo#418 “Match config when using format cmd `--stdin-filepath`”](https://github.com/tamasfe/taplo/pull/418) (merged, 2023-06-09).
- Comments can be schema directives (`#:schema`); their placement and exact syntax matter. [Directives](https://raw.githubusercontent.com/tamasfe/taplo/master/site/site/configuration/directives.md).
- Editor and CLI versions/settings are distinct surfaces; configuration changes sometimes require an extension reload. [tamasfe/taplo#274 “format ignores options when no `taplo.toml` file exists”](https://github.com/tamasfe/taplo/issues/274) (closed, 2022-06-21); [tamasfe/taplo#390 “Array always auto collapses even when configured not to”](https://github.com/tamasfe/taplo/issues/390) (open, 2023-03-27).

## TOML: toml-sort / TOMLKit

**Tool** — TOML; [toml-sort](https://github.com/pappasam/toml-sort) and [TOMLKit](https://github.com/python-poetry/tomlkit). Earliest fetched toml-sort release v0.1.0, 2019-08-06; first publication **unverified**. TOMLKit first release **unverified**. Sorting is explicit policy; preserving source trivia is TOMLKit’s purpose.
**Design choices that matter to us**

- toml-sort sorts tables by default; key and inline-array sorting are opt-in. [README](https://raw.githubusercontent.com/pappasam/toml-sort/main/README.md).
- Header/footer/inline/block comments have separate policies; orphan comments are explicitly removed. [README](https://raw.githubusercontent.com/pappasam/toml-sort/main/README.md).
- A blank line decides whether a comment is attached to an item or treated as a header/orphan. [README](https://raw.githubusercontent.com/pappasam/toml-sort/main/README.md).
- `pyproject.toml` supplies configuration; CLI options win; per-key overrides support patterns. [README](https://raw.githubusercontent.com/pappasam/toml-sort/main/README.md).
- Stdin defaults to stdout; `--in-place` is explicit and `--check` is read-only. [README](https://raw.githubusercontent.com/pappasam/toml-sort/main/README.md).
- TOMLKit retains syntax but editing/reclassifying tables still needs semantic regression tests. [python-poetry/tomlkit#98 “Comment before table causes next entry to be in table”](https://github.com/python-poetry/tomlkit/issues/98) (closed, 2020-05-07); [pappasam/toml-sort#103 “Keep dotted keys separate from table headers”](https://github.com/pappasam/toml-sort/pull/103) (closed, 2026-09-11).

## HOCON: ConfigDocument and library round trips

**Tool** — HOCON value renderers/editors; [Lightbend Config](https://github.com/lightbend/config), [pyhocon](https://github.com/chimpler/pyhocon), [PureConfig](https://github.com/pureconfig/pureconfig), [Configurate](https://github.com/SpongePowered/Configurate), [Erlang hocon](https://github.com/emqx/hocon). Libraries optimize reading/editing values; that is not an automatic source-formatting promise.
**Design choices that matter to us**

- ConfigDocument explicitly preserves source text/syntax; `Config.root().render()` renders a value tree. [API](https://raw.githubusercontent.com/lightbend/config/main/config/src/main/java/com/typesafe/config/parser/ConfigDocument.java); [NEWS](https://raw.githubusercontent.com/lightbend/config/main/NEWS.md).
- Public traversal of ConfigDocument’s node tree is still an open request; array-value editing is another API gap. [lightbend/config#300 “Public access to `ConfigNode` tree”](https://github.com/lightbend/config/issues/300) (open, 2015-04-02); [lightbend/config#671 “Is it possible to update object array with ConfigDocument”](https://github.com/lightbend/config/issues/671) (open, 2020-02-23).
- `withValueText` removes duplicate definitions before the last occurrence; this editor operation is not safe as a general formatting transform. [API](https://raw.githubusercontent.com/lightbend/config/main/config/src/main/java/com/typesafe/config/parser/ConfigDocument.java).
- `withValueText` rejects leading/trailing whitespace/comments in replacement text; JSON and HOCON parse modes differ. [API](https://raw.githubusercontent.com/lightbend/config/main/config/src/main/java/com/typesafe/config/parser/ConfigDocument.java).
- Plain pyhocon CLI conversion resolves substitutions and drops comments; an open request asks for actual formatting. [chimpler/pyhocon#336 “Use pyhocon CLI as a formatter”](https://github.com/chimpler/pyhocon/issues/336) (open, 2025-04-02); [chimpler/pyhocon#223 “Preserving comments during parsing”](https://github.com/chimpler/pyhocon/issues/223) (open, 2020-03-03).
- pyhocon supports unresolved-substitution conversion policies; those are conversion settings, not source preservation. [README](https://raw.githubusercontent.com/chimpler/pyhocon/master/README.md).
- PureConfig’s case-class writer can transform key names by derivation policy; it is not a lossless text editor. [pureconfig/pureconfig#782 “Scala 2.13.3 render issue with 0.12.3”](https://github.com/pureconfig/pureconfig/issues/782) (closed, 2020-06-26); [pureconfig/pureconfig#239 “CamelCase is converted to lowercase with hiphen”](https://github.com/pureconfig/pureconfig/issues/239) (closed, 2017-05-23).
- Configurate has its own node/order/comment layer and HOCON renderer changes; fixes there do not prove released sconfig behavior. [SpongePowered/Configurate#162 “HOCON ordering vs comments”](https://github.com/SpongePowered/Configurate/issues/162) (closed, 2020-07-25); [SpongePowered/Configurate#446 “hocon: setup vendor project, remove config sorting on write and use order preserving collections”](https://github.com/SpongePowered/Configurate/pull/446) (merged, 2023-11-08).
